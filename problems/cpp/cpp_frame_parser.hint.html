Byte-Stream Frame Parser State Machine

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

Persist everything in Parser, switch on the state

case 0: if (byte == 0xAA) state = 1;                        return 0
case 1: if (byte < 1 || byte > 16) state = 0; else start payload   return 0
case 2: store byte; sum = (uint8_t)(sum + byte); if full -> state 3  return 0
case 3: state = 0; return (uint8_t)(sum + byte) == 0 ? expected : 0

Validate the length in state 1, before state 2 ever stores a byte -- that single check is what keeps the payload array safe. Every path out of state 3 resets the state.

Where it goes wrong

This is where firmware earns its reputation. Trusting the length byte overwrites memory past the payload buffer, and the guard bytes will tell you. Resetting the state only on a good frame means one bad checksum eats the next frame's start byte too. Letting the 8-bit sum grow into an int breaks the "sums to zero" test for every valid frame. Keeping parser state in static locals works for the first test line and fails the second. Treat each of those as a separate test you can run by hand against the visible cases.
