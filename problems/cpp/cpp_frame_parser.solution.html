Byte-Stream Frame Parser State Machine

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

#include <cstdint>

struct Parser
{
    std::uint8_t state;
    std::uint8_t expected;
    std::uint8_t received;
    std::uint8_t sum;
    std::uint8_t payload[16];
    std::uint8_t guard[4];
};

int Feed(Parser& p, std::uint8_t byte)
{
    switch (p.state)
    {
    case 0:
        if (byte == 0xAA)
        {
            p.state = 1;
        }
        return 0;

    case 1:
        if (byte < 1 || byte > 16)
        {
            p.state = 0;
            return 0;
        }
        p.expected = byte;
        p.received = 0;
        p.sum = 0;
        p.state = 2;
        return 0;

    case 2:
        p.payload[p.received] = byte;
        p.received++;
        p.sum = static_cast<std::uint8_t>(p.sum + byte);
        if (p.received == p.expected)
        {
            p.state = 3;
        }
        return 0;

    default:
        p.state = 0;
        if (static_cast<std::uint8_t>(p.sum + byte) == 0)
        {
            return p.expected;
        }
        return 0;
    }
}

Why the length is checked in state 1

payload has sixteen slots. If a hostile or merely noisy link sends aa 20 ..., a parser that trusts the length would store thirty-two bytes into a sixteen-byte array and overwrite whatever follows it -- the classic firmware buffer overflow. Rejecting length < 1 || length > 16 at the moment the length byte arrives guarantees that received < expected <= 16 every time state 2 stores a byte.

Why every exit goes back to state 0

State 3 resets state before it even looks at the checksum, so a bad checksum and a good one both leave the parser ready for the next 0xAA. A parser that only resets on success sits in state 3 and treats the next frame's start byte as a checksum, losing that frame as well -- one corrupted byte costing two messages.

Why the state lives in the struct

Everything the machine remembers is in Parser, so a frame can be split across any number of calls, several links can be parsed independently, and the whole thing has no hidden static data to reset. In an interrupt-driven design, Feed is called with one byte per interrupt; it must do a small, bounded amount of work each time and never block or allocate.

Why the sum is narrowed

p.sum + byte is an int expression, so the 8-bit wrap-around must be restored by converting back to std::uint8_t. Comparing the unwrapped int with zero would fail for every frame whose payload and checksum add up to 0x100 -- that is, every valid frame.

Cost

O(1) per byte, with no heap and a fixed sizeof(Parser).
