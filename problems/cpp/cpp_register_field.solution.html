Read and Write a Register Bit Field

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

#include <cstdint>

static std::uint32_t Mask(unsigned width)
{
    return width >= 32 ? 0xFFFFFFFFu : ((1u << width) - 1u);
}

std::uint32_t ExtractField(std::uint32_t reg, unsigned pos, unsigned width)
{
    return (reg >> pos) & Mask(width);
}

std::uint32_t InsertField(std::uint32_t reg, unsigned pos, unsigned width,
                          std::uint32_t value)
{
    std::uint32_t mask = Mask(width) << pos;
    return (reg & ~mask) | ((value << pos) & mask);
}

Why width 32 needs its own mask

The usual mask expression is (1u << width) - 1. For width == 32 that shifts a 32-bit value by 32, which the C++ standard leaves undefined. On x86 the hardware silently reduces the count modulo 32, so the mask comes out as 0 and the "whole register" field reads as nothing; on other targets it can be anything. Handling 32 explicitly gives 0xFFFFFFFF everywhere.

Why the value is masked

value << pos alone puts every set bit of value into the result, including those above the field. Masking the shifted value with the field mask discards them, so writing 0x1F into a 4-bit field at bit 4 changes bits 4..7 only. The same masking is why a bad configuration value cannot silently reconfigure the neighbouring peripheral setting.

Why clear first

reg | (value << pos) can only set bits. Writing a zero field over an old non-zero one would leave the old bits behind. AND with the inverted mask first, then OR.

Cost

O(1): a few shifts and masks, no branches beyond the width test.
