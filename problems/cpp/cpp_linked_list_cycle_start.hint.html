Find Where a Linked-List Cycle Begins

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

Two phases: find a meeting point, then find the entrance

phase 1: slow = fast = head
         loop while fast && fast->next:
             slow = slow->next; fast = fast->next->next
             if slow == fast: -> phase 2
         (loop ends: no cycle, return nullptr)
phase 2: entry = head
         while entry != slow: entry = entry->next; slow = slow->next
         return entry

Phase 2 moves both pointers one step at a time. They are the same distance from the cycle's entrance (one going round the loop, the other down the tail), so they arrive there together.

Where it goes wrong

Interviewers use this as the follow-up to the simpler cycle-detection question precisely because the first answer people give is incomplete. Detecting that the two pointers meet only proves there is a cycle; the meeting node is somewhere inside it, not at its start. The second slip is dereferencing fast->next->next without checking fast->next, which crashes on every acyclic list of odd length. The third is comparing the pointers before moving them, which makes every list look circular. The harness prints the index it got back, so a wrong node is easy to spot.
