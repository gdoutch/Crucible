Sum Vectors With operator+

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

struct Vector2D
{
    double x;
    double y;
};

Vector2D operator+(const Vector2D& a, const Vector2D& b)
{
    return Vector2D{a.x + b.x, a.y + b.y};
}

Why it must be this exact free function

The harness declares Vector2D operator+(const Vector2D& a, const Vector2D& b); and calls it as total = total + v;. That declaration names a specific symbol the linker has to find: a free function taking two const Vector2D& parameters. A member-function version of operator+ (Vector2D Vector2D::operator+(const Vector2D& other) const) is legal C++ and would make a + b compile inside a translation unit that has that member function's declaration available -- but it is a genuinely different function from the one the harness forward-declared, and the harness's translation unit only ever sees the free-function declaration. The build fails at the link step -- "unresolved external symbol operator+" or similar -- rather than anywhere in your own source file, because nothing about your code is syntactically wrong, it just does not define the symbol the harness needs.

Why the parameters are `const Vector2D&`

Vector2D is small (two doubles, 16 bytes), so taking it by value instead would not be a *correctness* problem the way it would be for a large container -- but it is still needless copying twice per call for no benefit, and `const&` costs nothing while making clear that `operator+` only reads `a` and `b`, never modifies either one.

Why the addition is component-wise

`a.x + b.x` and `a.y + b.y` are independent, ordinary `double` additions -- there is no interaction between the x and y components in a vector sum, so nothing here can accidentally "cross" them the way a typo like `a.x + b.y` would. Constructing the result with `Vector2D{a.x + b.x, a.y + b.y}` keeps the two additions visually paired with the fields they belong to.

Cost

O(1) per call -- two `double` additions and one small struct returned by value, which for an object this size the compiler typically returns without any heap allocation at all.
