A Doubly Linked Chain Without Leaks

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

#include <memory>
#include <vector>

struct Node
{
    int value = 0;
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;
    ~Node();
};

std::shared_ptr<Node> BuildChain(const std::vector<int>& values)
{
    std::shared_ptr<Node> head;
    std::shared_ptr<Node> tail;
    for (int v : values)
    {
        std::shared_ptr<Node> node = std::make_shared<Node>();
        node->value = v;
        if (!head)
        {
            head = node;
        }
        else
        {
            tail->next = node;
            node->prev = tail;
        }
        tail = node;
    }
    return head;
}

Why prev must be weak

Each node's reference count is the number of shared_ptrs pointing at it. With a shared prev, node 2 is owned by node 1's next and node 3's prev. Dropping the head releases only the head's own reference; node 1 is still held by node 2's prev, node 2 by node 3's, and so on. The counts never reach zero, so no destructor runs. weak_ptr observes without counting: the only owners are the forward next links, so releasing the head cascades down the whole chain.

Why the local tail is safe

tail and node are locals; they go out of scope when BuildChain returns, leaving the head as the sole owner of node 1, node 1's next as the sole owner of node 2, and so on. That is exactly what makes the head's use_count() equal 1 in the harness.

Cost

O(n) time and one allocation per node (via make_shared).
