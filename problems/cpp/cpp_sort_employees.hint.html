Sort Records With a Comparator

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

Compare key by key, equal-then-next

[](const Employee& a, const Employee& b) {
    if (a.department != b.department) return a.department < b.department;
    if (a.salary     != b.salary)     return /* descending */;
    return a.name < b.name;
}

Each if asks "do these differ on this key?" and, if so, settles the whole comparison there. Only genuinely tied keys fall through to the next one -- and a full tie returns false.

Where it goes wrong

A comparator is a promise: it must be a strict weak ordering, and breaking the promise is undefined behaviour inside std::sort, not just a wrong order. Returning true for equal elements (<=) breaks it. Writing the salary comparison as a subtraction breaks it differently, because two large values of opposite sign overflow int and the sign flips -- the last visible test is built to expose exactly that. And remember the middle key runs the opposite way to the other two.
