Look up the complement, then remember yourself

for each j:
    need = target - values[j]          // in long long
    if need was seen: return {seenIndex[need], j}
    remember values[j] -> j            // only the first time

The order of those two steps is what stops an element pairing with itself. emplace leaves an existing key alone, which keeps the earliest index.

Where it goes wrong

Three separate things go wrong. Recording a value before looking it up lets an element pair with itself, so [3] with target 6 wrongly succeeds. Overwriting a repeated value's index in the map returns a larger i than the problem asks for. And target - values[j] is a signed subtraction that can overflow int -- the last visible test is built around that.
