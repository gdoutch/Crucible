Find Where a Linked-List Cycle Begins

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

struct ListNode
{
    int val;
    ListNode* next;
};

const ListNode* CycleStart(const ListNode* head)
{
    const ListNode* slow = head;
    const ListNode* fast = head;
    while (fast != nullptr && fast->next != nullptr)
    {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast)
        {
            const ListNode* entry = head;
            while (entry != slow)
            {
                entry = entry->next;
                slow = slow->next;
            }
            return entry;
        }
    }
    return nullptr;
}

Why the meeting point is not the answer

The fast pointer travels twice as far as the slow one. If the tail before the loop has length a, the loop has length L, and they meet b steps into the loop, then slow has walked a + b and fast 2(a + b). The difference, a + b, must be a whole number of laps: a + b = kL. So a = kL − b: walking a more steps from the meeting point takes you the rest of the way round the loop to its entrance. A pointer starting at head also reaches the entrance after exactly a steps. Moving both in lockstep makes them collide at the entrance, and only there. The first meeting point itself is b steps past the entrance, which is generally not the start.

Why the loop condition checks two pointers

The fast pointer advances two nodes per iteration. fast->next->next dereferences fast->next, so both fast and fast->next must be non-null first. Either being null means the list ended, so there is no cycle.

Why move before comparing

Both pointers start at head. Comparing them before the first step would find them equal immediately and report a cycle in every non-empty list.

Cost

O(n) time and O(1) extra space.
