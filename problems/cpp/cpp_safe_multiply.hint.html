Multiply Without Signed Overflow

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

Do the multiplication somewhere it cannot overflow

long long wide = (long long)a * b;      // two ints always fit
if (wide < INT_MIN || wide > INT_MAX) return false;
result = (int)wide;
return true;

The range check goes on the wide value, and nothing is written to result until it passes. INT_MIN * -1 needs no special case once you widen first.

Where it goes wrong

The instinct is to multiply and then test the result. In C++ that is the bug: signed overflow is undefined behaviour, so the program is already wrong by the time you test, and an optimiser may delete the test. A division-based check such as (a * b) / a == b has the same flaw and also divides by zero when a is 0. Two operand pairs deserve special attention because their true result is exactly one past INT_MAX.
