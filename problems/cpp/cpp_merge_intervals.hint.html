Merge Overlapping Intervals

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

Sort, then fold into the last merged interval

sort(intervals);
for (next : intervals) {
    if (!merged.empty() && next.first <= merged.back().second)
        merged.back().second = max(merged.back().second, next.second);
    else
        merged.push_back(next);
}

Once sorted by start, an interval either reaches back into the last merged one or starts a new one. The end must be max-ed, because the new interval can finish before the current one does.

Where it goes wrong

Three slips cover most failures. Merging only when intervals strictly overlap (<) leaves [1,2] and [2,3] apart although they share a point. Skipping the sort works only if the input happens to be in order. And assigning the new end instead of taking the larger of the two ends shrinks a result when a later interval sits wholly inside the current one. Guard the empty input too: there is no first interval to look at.
