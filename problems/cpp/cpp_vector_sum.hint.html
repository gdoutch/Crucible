Sum a Vector Without Overflowing

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

One accumulator, one loop

long long total = 0;
for (int v : values) {
    total += v;
}
return total;

That is the whole function -- the interesting part is not the loop, it is what type total is declared as.

Declare the accumulator's real type from the start

If total starts life as an int and only gets converted to long long in the return statement, every individual += along the way is still ordinary 32-bit addition -- the overflow has already happened, silently wrapped to a nonsense value, long before the conversion at the end ever runs. The fix is not the conversion; it is declaring long long total = 0; so every addition from the very first one is already 64-bit.

A range-for (for (int v : values)) reads each element without needing an explicit index -- and since the loop body only ever reads v, there is nothing here that needs values to be mutable.
