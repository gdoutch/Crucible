Lower Bound: the Leftmost Insertion Point

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

#include <vector>

int LowerBound(const std::vector<int>& sortedValues, int target)
{
    int low = 0;
    int high = static_cast<int>(sortedValues.size());
    while (low < high)
    {
        int mid = low + (high - low) / 2;
        if (sortedValues[mid] < target)
        {
            low = mid + 1;
        }
        else
        {
            high = mid;
        }
    }
    return low;
}

Why there is no "found it" branch

Two invariants hold throughout the loop, maintained by which bound moves on each comparison: every index strictly less than low holds a value known to be < target, and every index from high onward holds a value known to be >= target. When sortedValues[mid] < target, that mid element belongs in the "known smaller" region, so low moves past it; otherwise -- whether sortedValues[mid] is greater than or equal to target -- it belongs in the "known not smaller" region, so high moves down to it. Crucially, an equal element is treated exactly the same as a greater one: it narrows high, it never triggers an early return. That is what forces the search to keep looking leftward through a whole run of equal values instead of stopping on whichever one it happens to land on first.

Why the loop ends exactly on the leftmost index

The loop keeps narrowing the gap between low and high until they meet -- low == high -- at which point low is the first index the "known not smaller" region begins at. That holds whether the answer lands in the middle of the array, at 0 (target belongs before everything), or at sortedValues.size() (target belongs after everything, or is larger than every element): the same invariant produces the right answer at both ends and through any run of duplicates in between, with no separate case for any of them.

Cost

O(log n) in the length of `sortedValues` -- each comparison discards half of what remains to be searched, the same as an ordinary binary search; finding the leftmost of a run of duplicates costs nothing extra because the search was never going to stop early in the first place.
