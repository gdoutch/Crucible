Lower Bound: the Leftmost Insertion Point

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

Narrow toward the answer -- never toward a match

int low = 0;
int high = static_cast<int>(sortedValues.size());
while (low < high) {
    int mid = low + (high - low) / 2;
    if (sortedValues[mid] < target) low = mid + 1;
    else                             high = mid;
}
return low;

There is no branch here that says "found it, return". That absence is the whole trick.

Why "found it" would break duplicates

A binary search shaped around "if sortedValues[mid] == target, return mid immediately" answers a different question than this one asks: it tells you *an* index where the target sits, not the *first* one. With three equal elements in the array, that kind of search can stop on any of the three depending on where the midpoint calculations happen to land -- correct for "is it present", wrong for "where does the leftmost one live". The loop above never has a "found it" branch to short-circuit into; it only ever asks "is sortedValues[mid] too small", and narrows one bound or the other based on the answer, which is what makes it converge on the leftmost position regardless of how many duplicates there are.

Trace what low and high mean throughout: everything before low is known < target, and everything from high onward is known >= target. The loop ends when they meet, and that meeting point is the answer.
