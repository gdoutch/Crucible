Fixed-Size Ring Buffer (No Heap)

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

Let count decide, let the indices wrap

Push: if count == capacity -> return false (touch nothing)
      data[head] = value; head = (head + 1) % capacity; count++
Pop:  if count == 0        -> return false (touch nothing)
      value = data[tail]; tail = (tail + 1) % capacity; count--

Both functions check first and modify afterwards. Neither ever compares head with tail to decide whether the buffer is full or empty.

Where it goes wrong

The classic failure is deciding "full" or "empty" from head == tail. Both states have equal indices, so the test cannot tell them apart, and the buffer will report empty when full (or the reverse). The struct carries a count for exactly this reason. The next most common bug is advancing head or writing the byte before checking for room: a rejected Push then still corrupts state. And forgetting to wrap an index sends the next write one element past the end of data. The harness poisons the struct before calling Init, so an Init that skips a field will show up.
