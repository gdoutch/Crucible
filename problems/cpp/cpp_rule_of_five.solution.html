Rule of Five: An Owning Text Class

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

#include <cstddef>
#include <cstring>
#include <utility>

class Text
{
public:
    Text(const char* s);
    Text(const Text& other);
    Text(Text&& other) noexcept;
    Text& operator=(const Text& other);
    Text& operator=(Text&& other) noexcept;
    ~Text();

    const char* c_str() const;
    std::size_t size() const;
    void set_char(std::size_t i, char c);

private:
    char* data_;
    std::size_t size_;
};

Text::Text(const char* s)
    : data_(nullptr), size_(std::strlen(s))
{
    data_ = new char[size_ + 1];
    std::memcpy(data_, s, size_ + 1);
}

Text::Text(const Text& other)
    : data_(nullptr), size_(other.size_)
{
    data_ = new char[size_ + 1];
    std::memcpy(data_, other.c_str(), size_ + 1);
}

Text::Text(Text&& other) noexcept
    : data_(other.data_), size_(other.size_)
{
    other.data_ = nullptr;
    other.size_ = 0;
}

Text& Text::operator=(const Text& other)
{
    if (this != &other)
    {
        char* fresh = new char[other.size_ + 1];
        std::memcpy(fresh, other.c_str(), other.size_ + 1);
        delete[] data_;
        data_ = fresh;
        size_ = other.size_;
    }
    return *this;
}

Text& Text::operator=(Text&& other) noexcept
{
    if (this != &other)
    {
        delete[] data_;
        data_ = other.data_;
        size_ = other.size_;
        other.data_ = nullptr;
        other.size_ = 0;
    }
    return *this;
}

Text::~Text()
{
    delete[] data_;
}

const char* Text::c_str() const
{
    return data_ ? data_ : "";
}

std::size_t Text::size() const
{
    return size_;
}

void Text::set_char(std::size_t i, char c)
{
    data_[i] = c;
}

Why copy assignment allocates before it frees

Order matters in operator=(const Text&). The reference guards this != &other and also builds the new buffer before delete[]-ing the old one. Reverse that and a = a frees data_ and then memcpys from the block it just freed. (Allocating first also means an allocation failure leaves the object untouched.)

Why a move must null out the source

After Text d(std::move(a)), both a and d will eventually be destroyed. If a.data_ still holds the stolen pointer, both destructors delete[] it -- a double free. Setting the source's pointer to nullptr and its size to 0 makes its destructor a harmless delete[] nullptr. This is also why c_str() maps a null buffer to the literal "": a moved-from Text must remain safe to read.

Why the destructor is not enough

The compiler-generated copy members would copy the pointer value, so b.set_char(0, '#') would also change a, and both destructors would free one block. Writing the destructor without the other four fixes the leak but creates exactly that aliasing and double free.

Cost

Copies are O(n); moves are O(1).
