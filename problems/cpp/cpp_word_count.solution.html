Count Words With a String Stream

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

#include <sstream>
#include <string>

int CountWords(const std::string& text)
{
    std::istringstream stream(text);
    std::string word;
    int count = 0;
    while (stream >> word)
    {
        count++;
    }
    return count;
}

Why this needs no special handling for whitespace runs or edges

stream >> word is defined, by the standard library's own rules for extracting a whitespace-delimited token, to first skip any whitespace, then read characters up to the next whitespace character (or the end of the stream). Both halves of that definition do the work a hand-rolled splitter would otherwise need explicit code for: skipping first means leading whitespace never produces an empty leading token, and reading "up to the next whitespace" rather than "up to the next single space" means a run of several spaces is one separator, not several. The expression while (stream >> word) also does its own loop termination correctly: the extraction fails (and the while stops) exactly when there is nothing left to read, including for a `text` that is empty or entirely whitespace.

Why an `istringstream`, not `std::cin`

The function receives `text` as an in-memory string, not as something already sitting on standard input -- `std::istringstream` gives that string the exact same extraction interface `std::cin` has, without needing the data to actually come from a real input stream. The harness that calls this function reads the *line* from `std::cin` itself; everything after that point works on the string in memory.

Cost

O(n) in the length of `text` -- the stream visits each character once while scanning for whitespace boundaries, and each word is copied into `word` once, which is discarded and refilled every iteration.
