Reverse a String in Place

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

#include <string>
#include <utility>

void ReverseInPlace(std::string& text)
{
    int left = 0;
    int right = static_cast<int>(text.size()) - 1;
    while (left < right)
    {
        std::swap(text[left], text[right]);
        left++;
        right--;
    }
}

Why the parameter has to be a reference

C++ copies function arguments by default. A parameter declared std::string text (no &) would give the function its own private copy to reverse -- and that copy is destroyed the instant the function returns, taking the work with it. Nothing about that version is illegal or even warned about: it compiles cleanly, and inside the function text genuinely does end up reversed. The bug only shows up one level up, in the caller, whose own string was never the thing being modified. std::string& makes text another name for the caller's actual variable, so there is only ever one string in play.

Why left < right, not left <= right

For an odd-length string, the two indices meet at the middle character, which needs no swap -- it is being compared and exchanged with itself, which is harmless but pointless. < stops the loop the moment that would happen, one iteration earlier than <= would. For an even-length string, left and right cross by one without ever being equal, and < stops that case correctly too -- one condition handles both parities without a separate check for either.

The empty and single-character cases

An empty string has right == -1, so left < right (0 < -1) is false immediately and the loop body never runs. A one-character string has left == right == 0, also false immediately. Neither needs a guard written by hand -- the same loop condition that ends an even- or odd-length reversal also covers both of these correctly, because "nothing to swap" and "stop immediately" are the same outcome.

Cost

O(n) in the length of `text` -- each character is touched exactly once, by exactly one swap, and no copy of the string is ever made.
