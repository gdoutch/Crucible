Is This a Valid Binary Search Tree?

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

Pass the allowed interval down the tree

Check(node, lo, hi):          // lo and hi exclusive, wider than int
    if node is null       -> true
    if node.val <= lo or node.val >= hi -> false
    return Check(node.left,  lo, node.val)
        && Check(node.right, node.val, hi)

Going left, the node's own value becomes the new upper bound; going right, it becomes the new lower bound. That is how a node deep in the right subtree remembers it must still beat the root.

Where it goes wrong

The famous wrong answer checks each node only against its immediate children, or only against its parent. That accepts a tree whose violation sits several levels apart, like the 5 1 7 null null 4 8 example in the tests. Information about ancestors has to travel down the recursion. The second trap is how you represent "no bound yet": reaching for INT_MIN and INT_MAX rejects valid trees that contain those very values. Finally, the ordering is strict, so equal values fail.
