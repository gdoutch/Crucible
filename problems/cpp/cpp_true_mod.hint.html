A Modulo That Is Never Negative

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

Fix up the sign, once

int magnitude = b < 0 ? -b : b;
int r = a % b;
if (r < 0) {
    r += magnitude;
}
return r;

`r`'s magnitude is already guaranteed less than `magnitude` by `%`'s own definition -- one addition, only when `r` came back negative, is always enough to land it in `[0, magnitude)`.

The one input that has to be caught before this code even runs

`INT_MIN / -1` is the textbook case of signed integer overflow -- the mathematically correct answer, `2147483648`, does not fit in a 32-bit `int`. What is easy to miss is that C++ defines `%` in terms of `/` (`a % b` is specified so that `(a / b) * b + (a % b) == a`), which means `a % b` inherits the same undefined behaviour for the same inputs. `INT_MIN % -1` is not a special case the standard carves out an exception for -- on real hardware it triggers the identical fault plain division does, before your fix-up code, or anything else in the function, gets a chance to run.

The fix is to never let `a % b` execute for that one pair at all: check b == -1 first, and return the answer directly -- everything is evenly divisible by 1 (or -1), so the true remainder is always 0 regardless of what a is.
