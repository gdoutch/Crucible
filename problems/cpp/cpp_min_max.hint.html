Seed from the data, not from zero

int lo = values[0];
int hi = values[0];
for (std::size_t i = 1; i < values.size(); i++) {
    // update lo and hi
}
return {lo, hi};

A minimum of 0 or a maximum of 0 is only right when 0 happens to be in the array. Starting from the first element is right for every non-empty array, whatever its values.

Where it goes wrong

Start a running minimum at 0 and an all-positive array reports a smallest value that is not in it; start a maximum at 0 and an all-negative array does the same. Sentinels like INT_MAX and INT_MIN look safer but fail on an array made of exactly those values. The only value guaranteed to be in the array is its first element, so every later element can only replace the running answer with something genuinely smaller or larger. Check your code against the "all positive" and "all negative" test cases before anything else.
