Reverse a Singly Linked List

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

struct Node
{
    int value;
    Node* next;
};

Node* ReverseList(Node* head)
{
    Node* prev = nullptr;
    Node* current = head;
    while (current != nullptr)
    {
        Node* next = current->next;
        current->next = prev;
        prev = current;
        current = next;
    }
    return prev;
}

Why next is saved before anything is reassigned

Node* next = current->next; is the line that makes the rest of the function safe: it captures a pointer to what comes after current in the *original* list, before the very next line overwrites current->next to point backwards instead. Swap the order -- rewire current->next to prev first, then try to read "what came next" -- and there is nothing left to read: current->next now holds prev, not the rest of the original list, and everything downstream of current becomes unreachable memory the moment that happens. This is easy to miss on a short list, because reversing two nodes only ever touches the one link between them -- there is nothing further downstream to lose. A list of four or five nodes makes the bug obvious: everything after the first one or two nodes is gone.

Why prev, not current, is the return value

The loop's own condition, current != nullptr, is what ends it -- so by construction, current is always nullptr once the loop exits. prev, meanwhile, was advanced to current's value on the *previous* iteration, which means it is sitting on the last real node the loop touched: the original list's tail, now the new head. Returning current instead would always return nullptr, regardless of how many nodes were actually reversed.

Why an empty list needs no special case

head == nullptr means current starts as nullptr, so while (current != nullptr) is false immediately and the loop body never runs. The function falls straight through to return prev;, which is still nullptr -- the correct answer for reversing nothing.

Cost

O(n) in the number of nodes -- each node's next pointer is rewritten exactly once, and no new nodes are allocated: the existing nodes are relinked in place, which is what "O(1) extra space" means here.
