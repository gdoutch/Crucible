Erase-While-Iterating, Correctly

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

#include <algorithm>
#include <vector>

void RemoveMultiplesOf(std::vector<int>& values, int n)
{
    values.erase(
        std::remove_if(values.begin(), values.end(),
                       [n](int v) { return v % n == 0; }),
        values.end());
}

Why the naive erase-in-a-loop version loses an element after every removal

std::vector<T>::erase(it) shifts every element after it one slot to the left to fill the gap, and returns an iterator to whatever now occupies it's old position -- the element that used to be immediately after the one removed. A hand-written for loop that calls erase(it) and then relies on its own ++it to advance is, in the branch that erases, advancing *twice*: once implicitly, because erase already left the vector's storage positioned so the next element sits where it used to point, and once explicitly, via the loop's own increment. The element that landed in the gap is never examined. On a vector like [2, 4, 6, 3, 8, 5] removing multiples of 2, this concretely means 4 survives despite being a multiple, because it was the element sitting right after 2 the moment 2 was erased.

Why `std::remove_if` + `erase` avoids this entirely

std::remove_if does not shrink the vector or shift memory around per element the way repeated calls to erase do -- it performs a single linear pass, copying (or move-assigning) each surviving element into its correct compacted position as it goes, and never removes anything from the container itself. Only the final `values.erase(...)` call actually shrinks the vector, once, dropping everything from the returned iterator onward -- the leftover, now-duplicated tail elements that `remove_if` did not overwrite. There is exactly one point where elements are actually removed, so there is no iterator to keep synchronised against a container that is changing size out from under it.

Why zero needs no special case

0 % n is 0 for any nonzero n, so the same predicate that flags 4 or 6 as multiples of 2 flags every 0 in `values` too, without the predicate needing to name `0` at all.

Cost

O(n) in the length of `values` -- `remove_if` visits each element exactly once, and the trailing `erase` call destroys the leftover elements and adjusts the vector's size in one pass over just the removed tail, not the whole vector again.
