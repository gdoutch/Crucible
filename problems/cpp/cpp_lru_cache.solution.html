LRU Cache With list and unordered_map

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

#include <list>
#include <unordered_map>
#include <utility>

struct LruCache
{
    int capacity;
    std::list<std::pair<int, int>> order;
    std::unordered_map<int, std::list<std::pair<int, int>>::iterator> index;
};

int Get(LruCache& cache, int key)
{
    auto it = cache.index.find(key);
    if (it == cache.index.end())
    {
        return -1;
    }
    cache.order.splice(cache.order.begin(), cache.order, it->second);
    return it->second->second;
}

void Put(LruCache& cache, int key, int value)
{
    auto it = cache.index.find(key);
    if (it != cache.index.end())
    {
        it->second->second = value;
        cache.order.splice(cache.order.begin(), cache.order, it->second);
        return;
    }
    cache.order.emplace_front(key, value);
    cache.index[key] = cache.order.begin();
    if (static_cast<int>(cache.order.size()) > cache.capacity)
    {
        cache.index.erase(cache.order.back().first);
        cache.order.pop_back();
    }
}

Why splice

The map gives O(1) lookup of a node; the list gives O(1) reordering and O(1) removal of the oldest. splice moves a node between positions of the same list without copying or reallocating it, so the iterator stored in index still refers to that node afterwards. Erasing the node and inserting a new one would hand back a different iterator -- and the map would keep pointing at the destroyed node.

Why evict from both containers

Popping order.back() alone leaves its key in index pointing at a dead node: a later Get of that key would "hit" and dereference freed memory. Erase the key from index first (while back() is still readable), then pop the list.

Cost

Both Get and Put are O(1) on average.
