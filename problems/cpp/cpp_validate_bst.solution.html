Is This a Valid Binary Search Tree?

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

struct TreeNode
{
    int val;
    TreeNode* left;
    TreeNode* right;
};

static bool Check(const TreeNode* node, long long lo, long long hi)
{
    if (node == nullptr)
    {
        return true;
    }
    if (node->val <= lo || node->val >= hi)
    {
        return false;
    }
    return Check(node->left, lo, node->val) && Check(node->right, node->val, hi);
}

bool IsValidBst(const TreeNode* root)
{
    return Check(root, -(1LL << 40), (1LL << 40));
}

Why checking the parent is not enough

Take 5 with left child 1 and right child 7, and give 7 a left child 4. Every parent-child pair looks fine: 1 < 5, 7 > 5, and 4 < 7. But 4 lives in the right subtree of 5, so it must be greater than 5, and it is not. The violation spans two levels, so only a check that remembers every ancestor can see it. That is what (lo, hi) does: after going right from 5 the lower bound is 5, and it stays 5 however deep you go, so 4 is rejected.

Why the bounds are long long

With int bounds you need sentinel values for "unbounded", and the natural sentinels are INT_MIN and INT_MAX -- which are valid node values. A node holding INT_MIN would fail val > lo. Wider bounds (the reference uses ±240) can never equal an int, so every legal value passes the unbounded case.

Why strict comparisons

The checks <= lo and >= hi reject equality, so duplicates fail on whichever side they appear.

Alternative

An in-order traversal of a valid BST is strictly increasing; checking that against a running "previous value" (held in a long long or a pointer) is equally correct.

Cost

O(n) time, O(h) stack for a tree of height h.
