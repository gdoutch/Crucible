Allocate, copy the values across, return

int* data = new int[original.size];
for (int i = 0; i < original.size; i++) {
    data[i] = original.data[i];
}
return Box{data, original.size};

What compiles cleanly and is still wrong

return original; compiles. It runs without crashing. And it is exactly the bug this exercise is built around: `Box`'s default copy copies the `data` field's *value* -- the address it holds -- not the array that address points to. Both the original `Box` and the one this function returns end up with a `data` pointer that names the identical block of memory. A caller that mutates one and then reads the other sees the mutation, because as far as the heap is concerned there was only ever one array the whole time. Nothing about the type system flags this: a raw `int*` carries no information about who owns what it points to, or how many `Box`es currently think they own it.

Both fields need copying -- `size` as well as `data` -- and `data` specifically needs a *new* allocation, not a copy of the pointer's bit pattern.
