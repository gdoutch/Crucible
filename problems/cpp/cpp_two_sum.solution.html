Two Sum With a Hash Map

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

#include <climits>
#include <unordered_map>
#include <utility>
#include <vector>

std::pair<int, int> TwoSum(const std::vector<int>& values, int target)
{
    std::unordered_map<int, int> firstIndex;
    for (int j = 0; j < static_cast<int>(values.size()); j++)
    {
        long long need = static_cast<long long>(target) - values[j];
        if (need >= INT_MIN && need <= INT_MAX)
        {
            auto it = firstIndex.find(static_cast<int>(need));
            if (it != firstIndex.end())
            {
                return {it->second, j};
            }
        }
        firstIndex.emplace(values[j], j);
    }
    return {-1, -1};
}

Why look up before insert

If values[j] is recorded first, a lookup for target - values[j] can find j itself whenever values[j] * 2 == target, answering {j, j} for the single-element input [3]. Looking up first only ever finds earlier positions, which also guarantees i < j.

Why long long for the complement

target - values[j] is a signed subtraction that can leave the range of int, which is undefined behaviour. In long long it is exact; a complement outside int range cannot be in the map, so the lookup is skipped.

Cost

O(n) expected time and space.
