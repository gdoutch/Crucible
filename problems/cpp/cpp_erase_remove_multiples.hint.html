Erase-While-Iterating, Correctly

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

One call does the whole job

values.erase(
    std::remove_if(values.begin(), values.end(),
                   [n](int v) { return v % n == 0; }),
    values.end());

std::remove_if walks the vector once, shuffles every element that should *survive* toward the front, in order, and returns an iterator marking where the leftovers begin. erase then drops everything from that iterator to the real end, in one operation.

The loop this is here to replace

The version that looks natural to write by hand --

for (auto it = values.begin(); it != values.end(); ++it) {
    if (*it % n == 0) {
        values.erase(it);
    }
}

-- has a bug that does not announce itself: values.erase(it) already returns (and effectively leaves it sitting on) the element that slid into the removed one's old slot. The for loop's own ++it then advances *again*, past that element, without ever checking it. Two multiples of n standing next to each other is exactly the shape that exposes this: the first is removed correctly, and the one immediately after it is skipped and survives.

If you want to fix the hand-written loop instead of reaching for remove_if, the trick is to only advance the iterator in the branch that does *not* erase, and to assign erase's own return value back into it in the branch that does.
