Read and Write a Register Bit Field

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

Build the mask once, then clear and set

mask  = (width == 32) ? 0xFFFFFFFF : (1u << width) - 1;
extract: (reg >> pos) & mask
insert:  (reg & ~(mask << pos)) | ((value & mask) << pos)

Insert is two steps on purpose: clear the field in reg, then OR in the masked value shifted into place. Extract is the same mask applied after a shift the other way.

Where it goes wrong

Three bugs account for nearly every wrong answer. Building the mask as (1u << width) - 1 is undefined for a 32-bit field. Forgetting to mask value lets a too-wide value spill into the bits above the field. And OR-ing the new value in without first clearing the old field leaves old bits behind wherever the new value has a zero. Run through the visible tests with these in mind: the 32-bit and the 0x1F-into-4-bits cases are there on purpose.
