Sum a Vector Without Overflowing

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

#include <vector>

long long SumVector(const std::vector<int>& values)
{
    long long total = 0;
    for (int v : values)
    {
        total += v;
    }
    return total;
}

Why total is long long from its first line

total += v runs once per element, and every one of those additions happens in whatever type total was declared as. If that type is int, each addition is 32-bit, unchecked by default in C++ -- it wraps rather than raising any kind of error -- and by the time a later static_cast<long long>(total) would try to widen the result, the wrong answer has already been computed and stored. Declaring long long total = 0; up front means every one of those additions is a 64-bit addition from the start, with roughly nine quintillion of headroom rather than about two billion -- comfortably enough for any sum this function could realistically be asked to produce.

Why `const std::vector<int>&`, not `std::vector<int>`

Taking values by value would copy every element into a new vector just to read them once each and throw the copy away -- for a large vector, real, wasted work on every single call. const& gives the function direct read-only access to the caller's own vector: no copy, and the compiler enforces the "read-only" part by refusing to compile any attempt to modify values through it.

Why an empty vector needs no special case

total starts at 0, and a range-for over an empty vector simply never executes its body -- the function returns 0 without an explicit check, which is exactly what the sum of nothing should be.

Cost

O(n) in the length of `values` -- one pass, one addition per element, no allocation.
