Byte-Swap a Register (Endianness)

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

Four bytes, reversed: byte 0 moves to where byte 3 was, byte 3 moves to where byte 0 was, and the same swap happens between bytes 1 and 2. The bits inside each byte do not move relative to each other -- only which byte they belong to changes.

One byte, one line, four times

Pick a byte off value with a mask, move it to its new home with a shift, and OR the four results together. For byte 0 (the lowest byte), moving to the top:

(value & 0x000000FFu) << 24

The other three follow the same shape: mask out one byte, then shift it by the difference between where it is and where it needs to be. Byte 1 moves up 8 places, byte 2 moves down 8 places, byte 3 moves down 24.

Watch out

  • Get the shift amount for each byte from where it starts and where it ends up, not from a pattern you are guessing at. Byte n (counting from 0 at the bottom) always moves to byte 3 - n.
  • Do all four in one pass rather than building it up with several reassignments to the same variable -- it is easy to accidentally read a byte back out of value after an earlier line has already changed it.
Still stuck? A bigger nudge

All four masks and shifts, side by side:

ByteMaskMove
0 (lowest)0x000000FFleft 24
10x0000FF00left 8
20x00FF0000right 8
3 (highest)0xFF000000right 24

OR the four masked-and-shifted values together and that is the whole function.

Check yourself before you press Go

  • swap_endian32(0x12345678) → 0x78563412.
  • swap_endian32(0x000000FF) → 0xFF000000 -- the lowest byte lands at the top.
  • Swapping a value twice always returns the original value -- a quick way to sanity-check your own code by hand.
