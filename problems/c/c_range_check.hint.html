What you are being asked for

true if value is between low and high, inclusive of both ends; false otherwise. That is the entire specification — the interesting part of this problem is not the logic, it is the shape the logic is written in.

Do not write it the way it reads in English

"Is value between low and high" reads like a single comparison, and C lets you write it as one:

return low <= value <= high;

This compiles. It also does not check what it looks like it checks — work out what <= being left-associative actually does to this expression before you decide whether to use it.

The MISRA angle

  • The result type is bool, from <stdbool.h> — not an int returning 0 or 1.
  • Two comparisons, joined with &&, not one chained comparison. MISRA's essential type model is part of why the chained form is off the table, not just a style preference layered on top.

Check yourself before you press Go

  • in_range(5, 10, 20) is false — try it against your chained-comparison instinct and see whether it agrees.
  • in_range(10, 10, 20) and in_range(20, 10, 20) are both true — both ends are inside the range.
  • low == high is a legal range with exactly one value in it, not an error case.
