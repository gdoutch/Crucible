Count the Words

Worked solution

This page contains the complete answer and explains why each part of it is there.

The idea

This is the smallest interesting state machine there is. Two states — inside a word and outside a word — and one counter that ticks on a single transition: outside → inside.

Framing it that way makes every awkward case disappear. Leading spaces are just time spent in the outside state. A run of ten spaces is one transition into the outside state and nine no-ops. A trailing space ends a word that was already counted when it started. The empty string performs no transitions at all. None of these need code; they are consequences of counting the right event.

The code

int count_words(const char *s)
{
    int words = 0;
    int inside = 0;

    for (; *s != '\0'; s++) {
        if (*s == ' ' || *s == '\t') {
            inside = 0;
        } else if (!inside) {
            inside = 1;
            words++;
        }
    }

    return words;
}

inside starts at 0 because before you have read anything you are, by definition, not in a word. That single initialisation is what makes a leading space and a leading letter behave correctly without a branch for either.

The else if (!inside) arm handles the only interesting transition. The fourth combination — a non-space while already inside — falls off the end of the chain and does nothing, which is exactly right.

Two transitions, two words. Notice that the second space of each pair does nothing — setting a flag that is already clear is idempotent, and that is the whole reason runs of separators need no counting logic.

The fixed cases, and what each one breaks

CaseWhich wrong solution it catches
empty string "Count spaces, add one" returns 1. So does anything that assumes there is at least one word.
spaces only Also 1 under the naive counter, and a favourite of solutions that increment on every separator run.
one word, two words The base cases. If these fail, the transition logic itself is inverted.

Cost

O(n) time, O(1) space — two ints regardless of how long the line is. Nothing is allocated and the caller's string is not touched.

Variations you might reach for

isspace() instead of an explicit test. Reasonable, but it changes the specification: isspace also treats \n, \r, \v and \f as separators. The problem says spaces and tabs, and the harness has already stripped the newline off the line it read, so the two agree on this input — but be deliberate about it rather than lucky. If you do use it, cast: isspace((unsigned char)*s).

strtok. It would work, and it would also destroy the caller's buffer by writing terminators into it — impossible here, since the parameter is const char *. It also keeps state in a static variable, which makes it unusable from more than one thread. Reaching for it on a problem this size is a bad trade.

Counting on the wrong edge. Counting the inside → outside transition instead misses the last word whenever the line does not end in a space. It passes two words if that test happens to have a trailing space and fails otherwise — a genuinely confusing failure to debug, which is why counting on entry is the habit to build.
