Decimal to Roman Numeral String

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

One string out, written into a buffer the caller owns. No return value, no allocation, no printing — the harness does all of that.

The instinct to resist

Almost everyone starts here: emit M while the value is at least 1000, then D, then C… and then discovers that 4 comes out as IIII and 900 as DCCCC. So they add a fixing-up pass that finds those and rewrites them.

That pass is where the bugs live. It has to know six patterns, it has to apply them in the right order, and it has to not corrupt the string while editing it in place.

Delete the fix-up by making it unnecessary. Ask what the first approach was actually missing: it only knew about seven values — 1000, 500, 100, 50, 10, 5, 1. But there are thirteen values a Roman numeral can be built from. The other six are the subtractive pairs, and they are values in their own right, not exceptions to be patched afterwards.

Thirteen rows, largest first

Write out all thirteen in descending order of value:

1000  M       900  CM
 500  D       400  CD
 100  C        90  XC
  50  L        40  XL
  10  X         9  IX
   5  V         4  IV
   1  I

Interleaved into one descending list — 1000, 900, 500, 400, 100, 90, … — that table is the algorithm. Repeatedly take the largest row that still fits, append its symbol, subtract its value. When the value reaches zero you are done, and every subtractive pair has appeared exactly where it should, without a single special case.

Try it by hand on 1994 before you write anything. You should use four rows and get seven characters.

The ordering is not cosmetic. If 900 sits below 500 in your table, then 900 takes the D row first and you are back to DCCCC. Greedy is only correct against a table in strictly descending order.

Two loops, not one

A row can be needed three times running — MMM, CCC, XXX, III. So the inner step is a while, not an if: keep taking the same row until it no longer fits, then move down.

(Never four times, and that is not something you have to enforce. The subtractive rows sit between the plain ones and take the fourth repeat away before it can happen — one more thing the table does for you.)

Building the string

You are appending, so you need to remember where the end is. The tidiest way is to walk out itself:

*out++ = 'X';       /* write, then advance */

out is your own copy of the pointer, so moving it does not disturb the caller's. A symbol is one or two characters, so copy it with a small loop over its own '\0'.

Terminate it. The very last thing the function does is *out = '\0'; — after the loops, not inside them. Forget it and the caller reads whatever followed your last letter. The harness prefills its buffer and checks, so you will get UNTERMINATED rather than garbage, but only this harness is that kind to you.

What you do not have to do

  • Validate. value is always 1–3999.
  • Check the buffer size. 16 bytes is guaranteed, and it is exactly enough — the longest numeral in range is 3888, MMMDCCCLXXXVIII, fifteen characters.
  • Allocate or free anything.
Still stuck? A bigger nudge 
static const struct {
    int value;
    const char *symbol;
} ROMAN[] = {
    { 1000, "M" }, { 900, "CM" }, /* ...eleven more, descending... */
    { 1, "I" },
};

void to_roman(int value, char *out)
{
    size_t count = sizeof ROMAN / sizeof ROMAN[0];

    for (size_t i = 0; i < count; i++) {
        while (value >= ROMAN[i].value) {
            /* append ROMAN[i].symbol -- one or two characters */
            value -= ROMAN[i].value;
        }
    }
    *out = '\0';
}

sizeof ROMAN / sizeof ROMAN[0] is the row count, worked out by the compiler. It only works where the real array type is in scope, which it is here.

Check yourself before you press Go

  • 1 → I, 3 → III, 4 → IV.
  • All six pairs: 4 9 40 90 400 900 → IV IX XL XC CD CM.
  • 1994 → MCMXCIV, not MDCCCCXCIV.
  • 3999 → MMMCMXCIX, not MMMIM.
  • 3888 → fifteen characters, and still terminated.
