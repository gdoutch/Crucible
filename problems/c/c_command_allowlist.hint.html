Where to start

  • Never read what you have not yet bounded. List every byte you read, and next to each write the check that makes it safe.
  • paylen is attacker-controlled. Compare it with len before you use it to find the counter.
  • Order matters. A frame that is wrong in two ways returns the code of the first check in the table.
  • The allow-list is a table in the statement. Consider how to write it so that adding a fourth command means adding one line.
Still stuck?

A switch on the type is the simplest shape: each case checks its own payload length and range, and default is the rejection. The counter check is common to every case, so it belongs after the switch.

Before you run it

Read the test names in the app. Each one is a sentence about a case you might have missed. If you can predict the output of every one by hand, your design is probably right.
