Primes up to N

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

Every prime from 2 up to and including n, written ascending into out, and the count returned. The caller sized out for you.

Turn the question round

Testing each number for primality is the obvious approach, and it asks the same question over and over: "does anything divide this?" The sieve of Eratosthenes asks a cheaper question instead — it never tests anything for primality at all.

Instead of asking what divides this number, walk up from 2 and, every time you meet a number nobody has crossed out, cross out all of its multiples. Anything still standing when you reach it had no smaller factor — so it is prime, and you knew that without dividing once.

You need a scratch array of n + 1 flags to record the crossings out. Index it by the number itself, so composite[15] is about 15 — that wastes slots 0 and 1 and is worth every byte for the confusion it saves.

The shape

for value = 2 .. n:
    if value is already crossed out:
        skip it
    record value as prime
    cross out value*2, value*3, value*4, ... up to n

Nothing crosses out 2, so 2 is recorded and 4, 6, 8… fall. Then 3 survives and 6, 9, 12… fall. Then 4 is already down, so it is skipped — and crucially its multiples do not need crossing out again, because every multiple of 4 is also a multiple of 2.

Two refinements, one of which has a trap in it

Start crossing out at value * value. Anything smaller than that — say value * 3 when value is 7 — has a factor below value and was already crossed out when that smaller factor had its turn. Starting at the square skips a great deal of repeated work.

And that product is where the bug lives. With n anywhere near 46341, value * value in int arithmetic overflows — signed overflow, so undefined behaviour, and in practice a large negative number that then gets used as an array index. Compute the starting multiple in a long long, or guard the loop so value never exceeds the square root of n.

Housekeeping

  • n < 2 — including 0 and negatives — means zero primes and nothing written. Handle that before you allocate anything, or calloc(n + 1, …) gets a negative size.
  • calloc zeroes for you, which is what you want: "not crossed out" is the initial state. malloc would need an explicit clearing loop.
  • Whatever you allocate, free it — on every return path, including the failure ones.
  • A char array is enough for the flags. One byte per number rather than four.
Still stuck? A bigger nudge 
if (n < 2) {
    return 0;
}

char *composite = calloc((size_t)n + 1, sizeof *composite);
if (composite == NULL) {
    return 0;
}

int found = 0;
for (int value = 2; value <= n; value++) {
    if (composite[value]) {
        continue;
    }
    out[found++] = value;
    for (long long multiple = (long long)value * value;
         multiple <= n;
         multiple += value) {
        composite[multiple] = 1;
    }
}

free(composite);
return found;

Note the cast on (long long)value * value. Casting the result — (long long)(value * value) — is too late; the multiplication has already overflowed by then.

Check yourself before you press Go

  • n = 0, n = 1, n = -5 → 0, nothing written.
  • n = 2 → 1, and out[0] == 2.
  • n = 10 → 4: 2 3 5 7.
  • Is 1 excluded? It is not prime.
  • Does the output come out ascending? It should, for free.
