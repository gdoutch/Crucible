Compute the Parity Bit

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

Whether value has an odd or an even number of set bits -- 1 for odd, 0 for even. That is all "the parity bit" is: the one extra bit that would make the total count even if you appended it.

The way you already know

If you have solved Count the Set Bits, you already have a function that answers a harder version of this question. Parity is just that count, looked at one way:

return count_set_bits(value) & 1;

That is a completely acceptable answer. It is also more work than the question needs -- counting every bit to find out only whether the total is odd or even.

A trick that never counts anything

XOR two bits together and the result is 1 exactly when they differ -- which is another way of saying it tracks parity for those two bits on its own. Chain that idea across the whole word: XOR the top half of value into the bottom half, and the bottom 16 bits now carry the same overall parity as the original 32. Halve again, and again -- five halvings take 32 bits down to a single one.

v ^= v >> 16;
v ^= v >> 8;
/* ...and so on, down to >> 1 */

The last bit left, v & 1, is the answer.

Watch out

  • The parameter is unsigned int for the same reason it is in Count the Set Bits: a right shift on an unsigned value always brings in zeros from the top, which is what a fold like this depends on. Keep any working variable you introduce unsigned too.
  • How many times do you need to halve 32 to reach 1? Get the number of fold steps right, or the top bits never make it down to where you are reading the answer from.

Check yourself before you press Go

  • even_parity(0) → 0 -- zero bits is even.
  • even_parity(1) → 1.
  • even_parity(0xFFFFFFFF) → 0 -- 32 set bits is even.
