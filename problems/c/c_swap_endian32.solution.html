Byte-Swap a Register (Endianness)

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

unsigned int swap_endian32(unsigned int value)
{
    return ((value & 0x000000FFu) << 24) |
           ((value & 0x0000FF00u) << 8)  |
           ((value & 0x00FF0000u) >> 8)  |
           ((value & 0xFF000000u) >> 24);
}

Four independent operations on the same value, combined with OR. Nothing here depends on the order they run in, which is what makes this version safe to write as one expression instead of four statements that each mutate a running total.

Walking it through

swap_endian32(0x12345678) -- each byte isolated, then moved:

ByteMaskedShiftMoved
0x78 (lowest)0x00000078<< 240x78000000
0x560x00005600<< 80x00560000
0x340x00340000>> 80x00003400
0x12 (highest)0x12000000>> 240x00000012

OR the "moved" column together: 0x78000000 | 0x00560000 | 0x00003400 | 0x00000012 = 0x78563412. Each byte lands in exactly one final position, so the four ORs never collide.

Why mask before shifting, not after

Masking first confines each byte to its own field before it moves, so shifting it can never spill into a neighbour -- the bits above and below the masked byte are already zero, and shifting zero produces more zero. Shifting first and masking the result afterwards works out identically for this particular function, because unsigned int shifts are well-defined and simply discard whatever falls off either end -- but mask-then-shift is the version that generalises, including to problems like Write a Register Field where the value being masked is not already confined to the type's full width.

Why it is its own inverse

Swapping reverses a specific pairing -- (0,3) and (1,2) -- and reversing the same pairing a second time returns every byte to where it started. That makes swap_endian32 an involution: the same function converts a value in either direction between big-endian and little-endian byte order, because "swap the bytes" does not need to know which direction it is being asked to go.

This is also a fast way to sanity-check your own implementation before running the tests: swap_endian32(swap_endian32(x)) must equal x for every x. If it does not, the four mask/shift pairs are not exact mirrors of each other.

At work, reach for the intrinsic

This exercise is worth writing out by hand once. In real code, the platform already has a single instruction for it: __builtin_bswap32 on GCC and Clang, _byteswap_ulong on MSVC, or htonl/ntohl from <arpa/inet.h> on POSIX systems specifically for network byte order. Any of them compiles to one bswap instruction, with no masks to get backwards.

Cost

Four masks, four shifts, three ORs -- fixed regardless of the input: O(1) time and space.
