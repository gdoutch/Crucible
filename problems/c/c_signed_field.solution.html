Extract a Signed Sensor Reading

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

int extract_signed_field(unsigned int reg, int start, int width)
{
    unsigned int mask = (width == 32) ? 0xFFFFFFFFu : (1u << width) - 1u;
    unsigned int field = (reg >> start) & mask;
    unsigned int sign_bit = 1u << (width - 1);

    if (field & sign_bit) {
        field -= sign_bit << 1;
    }
    return (int)field;
}

The first two lines are Extract a Register Field exactly. The rest is what turns an unsigned field into the signed number it represents.

What "sign-extend" actually means

A width-bit two's-complement value only means something different from its plain unsigned reading when the top bit — bit width - 1 — is set. When it is, the value the bits represent is field - 2^width, not field. Four bits, concretely:

BitsUnsignedTwo's complement
011177 (top bit clear -- no change)
100088 − 16 = −8
11111515 − 16 = −1

sign_bit is 1u << (width - 1) — the top bit of the field, on its own. sign_bit << 1 is 2^width, computed by shifting that same bit one further rather than writing a second, separate 1u << width — which matters, because width itself can be 32, and a fresh 1u << width would hit the same undefined shift as the mask. sign_bit << 1 shifts by a constant 1 instead, which is always safe: shifting a 1 bit out of the top of an unsigned type is well defined, it just discards it, giving 0 — and at width == 32 that is exactly the right answer, because subtracting 0 leaves the full 32-bit pattern to be reinterpreted by the final cast, which is what a full-width field needs anyway.

The trap: whose top bit?

The sign bit is bit width - 1 of field — the value after shifting and masking — never bit 31 of reg itself. A 12-bit reading packed into a 16-bit register shares that register with four other bits that have nothing to do with this field's sign; a reading packed into the low byte of a 32-bit register shares it with 24 bits that have even less to do with it.

Two of the fixed tests use the same upper bits of reg and differ only in the field itself, specifically so that "which bit did you actually test" cannot be dodged by accident:

  • extract_signed_field(0xABCDEF7F, 0, 8) — bit 31 of the register is 1, but the field is bits 0-7, and its own top bit (bit 7 of the field, value 0x7F) is 0. The field is positive: 127. Testing bit 31 instead of bit 7 gets this backwards.
  • extract_signed_field(0x23CDEF80, 0, 8) — the mirror image: bit 31 of the register is now 0, but the field's own top bit is 1 (0x80). The field is negative: -128. Testing bit 31 gets this one backwards too, in the other direction.

Together the pair rules out "test some fixed bit of the register" entirely — whichever bit a wrong implementation happens to test, one of the two cases sets it to disagree with the field's actual sign.

The other trap, carried over

width == 32 needs the mask formula's special case for the same reason it does in Extract a Register Field and Write a Register Field: 1u << 32 is undefined behaviour, not a value that saturates usefully. extract_signed_field(0xFFFFFFFF, 0, 32) — the whole register reinterpreted as signed — is -1, and is one of the fixed tests.

An alternative worth knowing: shift, don't subtract

The classic version of this trick sign-extends with two shifts instead of a branch and a subtraction:

int shifted = (int)(reg << (32 - start - width));  /* field's sign bit -> bit 31 */
return shifted >> (32 - width);                     /* arithmetic shift back down */

Left-shifting puts the field's own top bit exactly on bit 31 of a 32-bit value; right-shifting a signed value back down copies that bit into every position it passes over, which is sign extension in hardware, for free. It is neat, and it is the same implementation-defined territory as the shift version of Count the Set Bits: right-shifting a negative signed int is not required by the standard to sign-extend, even though every mainstream compiler does exactly that. The branch-and-subtract version above stays in unsigned arithmetic until the one cast at the very end, which is why it is the one written out as the primary answer here.

Cost

A handful of operators and one branch, no loop: O(1) time and space for any width.
