Slew-Rate Limit a Demand Signal

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

int slew_limit(int previous_output, int target, int max_step)
{
    int delta = target - previous_output;

    if (delta > max_step) {
        delta = max_step;
    }
    if (delta < -max_step) {
        delta = -max_step;
    }
    return previous_output + delta;
}

Why both clamps are needed

delta can be positive or negative depending on which side of previous_output the target currently sits on -- there is nothing in the function's job that only ever moves the output upward. The fixed test that ramps up toward 100 and then reverses to -50 exists specifically to exercise both clamps in the same run: an implementation with only the first if -- clamping the positive side and leaving negative deltas untouched -- passes every step of the ramp up and then jumps straight to the reversed target in one move, because nothing stopped a large negative delta.

Landing exactly on the target

Neither clamp fires when delta is already within [-max_step, max_step] -- the two ifs are only ever entered when the direct move would exceed the cap. A target 3 away with a cap of 100 leaves delta unchanged at 3, and previous_output + delta lands exactly on the target in one call. Called again with the same target, delta is now 0, both clamps are no-ops, and the output holds -- there is no separate "have I arrived" check anywhere, because the arithmetic already produces the right answer in that case without one.

Why a real system limits the rate at all

An instant jump in a demand signal is rarely something the thing receiving it can or should follow instantly -- a valve has physical inertia, a motor has a torque limit, and even where nothing physical is in the way, a step change is often exactly what causes the overshoot and ringing a well-tuned system is trying to avoid in the first place. Capping how fast the demand itself is allowed to move is the simplest available tool for keeping the rest of the control chain inside its comfortable operating range, upstream of anything a controller further down the chain has to compensate for.

Cost

Two comparisons and one addition per call, independent of how far the target is: O(1) time and space.
