Reverse a Linked List

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

Turn every next pointer round and return the node that is now at the front. Relink the nodes — copying the values into an array, reversing it, and writing them back produces the right output and avoids the entire exercise.

The one hard fact about singly linked lists

A node knows what comes after it and nothing about what came before. So the instant you write node->next = something_else, the rest of the list is unreachable — unless you saved that pointer first.

This is the whole problem in one sentence: save next before you overwrite it. There is no recovery. The nodes still exist, nothing has been freed, and no pointer in your program refers to them any more.

Three pointers

Picture yourself standing on one node, mid-reversal:

already reversed          not yet touched
   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐
   │ a │◄──│ b │   │ c │──►│ d │──►│ e │──► NULL
   └───┘   └───┘   └───┘   └───┘   └───┘
             ▲       ▲       ▲
          previous  head    next
  • previous — the head of the part already reversed. Starts as NULL, because the first node's next must end up null.
  • head — the node being turned round right now.
  • next — a copy of head->next, taken before the damage, so you can still get to the rest of the list.

Work out the four steps of one iteration yourself: save, relink, then shuffle the two names along. Getting them in the wrong order is what the exercise tests.

Where does the loop stop, and what do you return?

The loop ends when head becomes NULL — you have walked off the end. At that moment head is null and useless, and previous is sitting on the last node you processed, which is the original tail. That is your new head.

So the return value is not head.

The edge cases fall out

  • Empty list. head is NULL, the loop never runs, and previous is still NULL — which is exactly what should be returned.
  • One node. One iteration. Its next is set to previous, which is NULL — it was already null, so nothing changes, and the node comes back as its own head.
  • The old head becomes the tail, so its next must finish as NULL. That is what initialising previous = NULL arranges.

If you find yourself writing if (head == NULL) return NULL;, check whether the loop already handles it.

Memory

Do not malloc and do not free. The caller owns the nodes, and will free the list you hand back. Allocating new nodes leaks the old ones; freeing them hands the caller a list of dangling pointers.

Still stuck? A bigger nudge 
struct node *previous = NULL;

while (head != NULL) {
    struct node *next = head->next;   /* 1. save */
    head->next = previous;            /* 2. turn this link round */
    previous = head;                  /* 3. advance previous */
    head = next;                      /* 4. advance head */
}

return previous;

Four lines, and each one must come after the one above it. Try reordering any pair on paper and watch the list fall apart.

Check yourself before you press Go

  • Empty list → NULL, no dereference.
  • One node → the same node, next still NULL.
  • Two nodes 1 2 → 2 1. The smallest list where the links really move.
  • Did you allocate anything? You should not have.
  • A crash here is almost always a next that was overwritten before it was saved.
