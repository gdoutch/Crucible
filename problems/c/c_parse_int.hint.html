Parse an Integer

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

A parser with a two-part result: a success flag as the return value, and the parsed number through an out-parameter. That shape — int f(input, output *out) — is everywhere in C, because there is no return value you could reserve to mean "failed" without also making it unparseable.

The grammar, precisely

number  :=  sign? digit+ end-of-string
sign    :=  '+' | '-'
digit   :=  '0'..'9'

Read that as three obligations, and notice that two of them are about what must not be there:

  1. An optional sign, at most one, only at the very front.
  2. At least one digit. This is what rejects "", "-" and "+".
  3. Nothing after the digits at all — the next thing must be '\0'. This is what rejects "12a", and it is the habit the problem exists to build.

Why not atoi

atoi("12a") returns 12. It stops at the first character it does not understand and tells you nothing about it — and atoi("banana") returns 0, indistinguishable from atoi("0"). It cannot report failure, so it cannot be used correctly on input you did not write yourself.

You are writing the thing atoi should have been. The distinguishing feature is the third obligation above.

Building the value

Left to right, one digit at a time:

value = value * 10 + (*s - '0');

*s - '0' works because the C standard guarantees the ten digit characters are consecutive and in order — a promise it makes for digits and pointedly does not make for letters.

Three details worth settling in advance

  • Remember the sign, apply it at the end. Accumulate the magnitude positively and negate once at the finish. Trying to accumulate negatively as you go is possible but fiddly.
  • Do not touch *out until you have decided to succeed. The contract says a rejected string leaves the caller's variable alone, so every return 0 must happen before the write.
  • Leading zeros are fine. "007" is 7. The arithmetic gives you that for free — do not add a rule against it.
Still stuck? A bigger nudge 
if (s == NULL || *s == '\0') {
    return 0;
}

int negative = 0;
if (*s == '+' || *s == '-') {
    negative = (*s == '-');
    s++;
}
if (*s == '\0') {
    return 0;                 /* a sign and nothing else */
}

long long value = 0;
for (; *s != '\0'; s++) {
    if (/* *s is not a digit */) {
        return 0;
    }
    value = value * 10 + (*s - '0');
}

*out = (int)(negative ? -value : value);
return 1;

Note the second *s == '\0' check. Without it, a lone "-" reaches the loop, the loop's condition is false immediately, and zero digits are accepted as the number 0.
