Elapsed Ticks Since a Free-Running Counter (MISRA Unsigned Arithmetic)

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

Two readings of a free-running counter that wraps back to 0 after UINT32_MAX instead of stopping. Return how many ticks passed between them — whether or not the counter wrapped in between.

The true elapsed time is guaranteed to be less than one full lap of the counter, so there is always a single unambiguous answer, wrap or no wrap.

Resist the urge to branch

The obvious-looking defensive version checks which reading is numerically bigger and does something different depending on the answer. Before you write that: what does plain subtraction on uint32_t actually do in C when the left side is smaller than the right side? It is not the same answer signed subtraction would give you.

The MISRA angle

Directive 4.6 says use the sized types from <stdint.h>. Here that is not just about precision — the type you pick changes what the subtraction below it means, and one of the two obvious choices is well-defined while the other is not.

Check yourself before you press Go

  • ticks_elapsed(5000, 1000) is 4000 — the ordinary case, no wrap involved.
  • ticks_elapsed(99, 100) — now is numerically less than start. The answer is not a small number and it is not negative.
  • If your implementation has an if in it, ask what it is doing that the type is not already doing for you.
