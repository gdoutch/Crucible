Add Hysteresis to a Noisy Threshold (Schmitt Trigger)

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

int schmitt_update(int reading, int low, int high, int previous_state)
{
    if (!previous_state && reading >= high) {
        return 1;
    }
    if (previous_state && reading <= low) {
        return 0;
    }
    return previous_state;
}

Why two thresholds beat one

A single threshold has one failure mode a noisy signal finds immediately: sitting right on top of it. Every bit of noise the sensor adds crosses the line, and every crossing flips the output -- a relay or a downstream state machine sees rapid, meaningless chatter instead of one clean transition.

Splitting into low and high fixes it by making the two transitions ask different questions. Turning ON requires clearing the higher of the two thresholds; turning OFF requires falling below the lower one. A signal has to move a real distance -- the gap between low and high -- to flip the output either way, and ordinary sensor noise is, by construction of the gap being wider than the noise, not enough to do that. The fixed test that hovers every reading strictly between low and high is checking exactly this: none of those readings clears either threshold, so the state -- whichever it started as -- never moves.

Walking a crossing through

Thresholds low = 20, high = 80, starting OFF, readings 10, 30, 50, 79, 80, 60, 21, 20, 19:

ReadingRule that appliesState
10, 30, 50, 79OFF and below high0
80OFF and reading >= high1
60, 21ON and above low1
20ON and reading <= low0
19OFF and below high0

The reading of exactly 80 turns the output on -- the threshold is inclusive -- and it then takes a reading down at 20, not merely below 80 again, to turn it back off.

Hysteresis versus debouncing

Both techniques exist to stop noise from producing a spurious state change, and it is easy to reach for either one out of habit without asking which kind of noise is actually present:

  • Hysteresis (this exercise) rejects noise in the value. One reading is enough to act on, as long as it clears a wide enough gap from wherever the last transition happened.
  • Debouncing a mechanical switch rejects noise in time. A single reading is never enough on its own -- several consecutive samples have to agree before the new state is trusted, no matter how far the raw signal moved.

A system with both kinds of noise -- a bouncy switch feeding a value that is also electrically noisy -- can legitimately need both techniques stacked, one after the other.

Cost

Two comparisons per call, no memory beyond the one state bit the caller already carries between calls: O(1) time and space.
