A Shift-Based Low-Pass Filter (No Floats)

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

An exponential moving average, the version that never needs a float. The ordinary formula is output += alpha * (sample - output) with alpha a fraction between 0 and 1. Replace the fractional multiply with a right shift, and alpha becomes "how many bits" instead of a fraction:

output += (sample - output) >> shift;

That line is the whole function.

The trap the problem is built around

sample - previous_output is a signed quantity -- the filter has to correct downward just as often as upward -- and a right shift only sign-extends correctly on a signed type. If a working variable for the difference ends up unsigned int -- an easy slip after a run of earlier exercises in this set that deliberately push everything unsigned -- a negative correction becomes a huge positive number instead, because an unsigned shift brings in zero bits from the top rather than copies of the sign bit. The output does not drift slightly wrong; it jumps to something wildly, obviously wrong on the very first sample below the current output. Keep previous_output, sample, and anything derived from their difference as plain signed int.

Something to notice, not to fix

One of the fixed tests holds previous_output at 100, feeds in a constant sample of 105 with shift = 4, and the output never moves. That is correct: the gap is 5, and 5 >> 4 is 0 -- there is no bug to find here, just a real property of this exact filter worth knowing about before you rely on it for something where it matters.

Check yourself before you press Go

  • Starting at 100 with shift = 2, a constant sample of 200 climbs steadily: 125, 143, 157, ... -- never reaching 200 exactly, always closing part of the remaining gap.
  • Starting at 100 with shift = 1, a constant sample of 90 reaches 90 exactly within a few calls and then holds.
