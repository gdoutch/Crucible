Reverse a String In Place

Worked solution

This page contains the complete answer and explains why each part of it is there.

The idea

Swap the ends inwards. Index 0 trades places with the last character, 1 with the second-last, and so on until the two indices meet in the middle. Half as many swaps as there are characters, no extra memory, and the terminator never moves because it is never one of the characters you touch.

The code

#include <string.h>

void reverse_string(char *s)
{
    size_t length = strlen(s);
    if (length < 2) {
        return;
    }
    for (size_t i = 0, j = length - 1; i < j; i++, j--) {
        char swap = s[i];
        s[i] = s[j];
        s[j] = swap;
    }
}

The guard is not politeness, it is necessity

strlen returns size_t, which is unsigned. When length is 0, the expression length - 1 does not evaluate to -1 — unsigned arithmetic wraps, so it evaluates to SIZE_MAX (18446744073709551615 on a 64-bit build).

Without the guard, the empty string sets j to that value, the condition 0 < SIZE_MAX is true, and the first swap reads and writes s[SIZE_MAX]. That is not a subtle off-by-one; it is a wild pointer, and it is why the empty string test case exists.

The length < 2 form covers the one-character case at the same time. A single character is already its own reverse, so returning early is correct as well as convenient — though note that with length == 1 the loop would have been harmless anyway (i and j both 0, condition false immediately). Only the zero case is dangerous.

If you prefer to avoid the special case altogether, walking pointers works and never forms the dangerous subtraction:

char *front = s;
char *back = s + strlen(s);
while (front < back--) {          /* back moves before the body runs */
    char swap = *front;
    *front++ = *back;
    *back = swap;
}

That version is cleverer and harder to read. The explicit guard is the better answer in code anyone else has to maintain.

Why i < j and not i <= j

For an odd length the two indices land on the same middle character, and i <= j would swap it with itself — correct but pointless. For an even length they never coincide; they cross. So the strict comparison is the one that terminates correctly in both cases, and it happens to skip the useless self-swap for free.

Continuing past the crossing point would undo the work: every pair gets swapped a second time and you get the original string back.

Walking a case

hello, length 5:

i, jSwapBuffer after
0, 4h ↔ ooellh
1, 3e ↔ lolleh
2, 2—loop ends, 2 < 2 is false

The '\0' sat at index 5 throughout and was never a candidate for either index, so strlen still returns 5 afterwards.

Cost

O(n) time — strlen is one pass and the swap loop is half a pass — and O(1) space: one char temporary, whatever the string's length.

Wrong turns worth recognising

Including the terminator in the reversal. Setting j = strlen(s) puts the '\0' at the front on the first swap. Everything printed afterwards is an empty string, and the real characters are still sitting in the buffer where nothing will ever read them.

Building the answer somewhere else. char *out = malloc(...), fill it backwards, then… what? You cannot make the caller's char * point at your new buffer — the pointer was passed by value. You would have to copy it back and free it, which is more code, slower, and can fail. "In place" is in the title for a reason.

Reversing a string literal. Not something this harness can do to you, but worth knowing: char *s = "hello"; reverse_string(s); is undefined behaviour, because string literals live in read-only memory. char s[] = "hello" gives you a writable array instead.
