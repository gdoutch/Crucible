Classify a Diagnostic Fault Code (MISRA Switch Rules)

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

A lookup from fault code to severity. Not a range check, not a formula — a fixed table with seven documented entries, and one more rule for everything that is not in it.

CodeMeaningSeverity
0no fault0
101, 102, 103sensor faults1
201, 202actuator faults2
301brake actuator fault3
anything elseundocumented-1

The MISRA shape, without giving away the logic

  • A switch on code, not a chain of if/else. The whole point of this problem is the switch-statement rules below — an equivalent if chain would dodge the exercise, not solve it.
  • Every clause ends in break; — Rule 16.3. Stacking bare case labels with nothing between them (case 101: case 102: case 103:) is fine; a clause that runs code and then falls into the next one is not.
  • A default clause, always — Rule 16.4. It is not there for completeness, it is there because most of int32_t is not a documented code.
  • One return, at the end, not one per case — Rule 15.5. Assign to a result variable inside the switch and return it once, after the switch ends.

The trap the problem is built around

The codes look like they cluster by range — 101-103 are all sensors, 201-202 are both actuators — and it is tempting to write that as a range check instead of enumerating each code: if (code >= 100 && code < 200) severity = 1; Fewer lines, looks equivalent.

It is not. 150 falls inside 100-199 but is not one of the three documented sensor codes, and a fixed test queries exactly that gap. The table only documents the codes it documents — enumerate them, do not infer a pattern from how they happen to be spaced.

Watch out, beyond the range-check trap

  • Negative codes are legal input and are always unknown — they should land in default without crashing, not be treated as a special case.
  • A run of queries in one test are independent of each other — nothing about classifying one code should depend on what was classified before it.

Check yourself before you press Go

  • classify_fault(301) is 3, the highest documented severity.
  • classify_fault(150) is -1 — close to real codes is not the same as being one.
  • classify_fault(-42) is -1, not a crash.
