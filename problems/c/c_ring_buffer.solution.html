Single-Producer/Single-Consumer Ring Buffer

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

int ring_push(int *buf, int capacity, int *head, int *tail, int value)
{
    int next = (*head + 1) % capacity;
    if (next == *tail) {
        return 0;
    }
    buf[*head] = value;
    *head = next;
    return 1;
}

int ring_pop(int *buf, int capacity, int *head, int *tail, int *value_out)
{
    if (*tail == *head) {
        return 0;
    }
    *value_out = buf[*tail];
    *tail = (*tail + 1) % capacity;
    return 1;
}

Why one slot has to stay empty

With only two indices to work with, the buffer's entire state -- how many items it holds, whether it is full, whether it is empty -- has to be recoverable from head and tail alone. If a full buffer were allowed to reach head == tail (by holding exactly capacity items), that pair of indices would mean two contradictory things at once, and there would be no way to tell which one you were looking at without a third piece of state.

Reserving one slot sidesteps the contradiction: ring_push computes where head would move to, and if that next position is tail, it refuses the write instead of performing it. The buffer therefore never reaches head == tail by pushing -- only by popping everything back out -- so that state can mean empty and only empty. The fixed test that fills a capacity-4 buffer with four pushes is checking precisely this: the fourth push would make head land on tail, so it is rejected, and the buffer tops out at 3 items held, not 4.

Why the checks read the way they do

ring_push checks where it would end up (next == *tail) rather than where it currently is, because the decision is about whether advancing is safe, not about the current state on its own. ring_pop's check is simpler -- *tail == *head directly means there is nothing between them to read -- because popping never needs to look ahead the way pushing does.

Order of operations: use the index, then move it

Both functions write or read at the current index before advancing it. buf[*head] = value; happens before *head = next;; *value_out = buf[*tail]; happens before *tail moves. Swap the order in either function and the first call touches slot 1 while claiming to have touched slot 0 -- every push and pop after that is one slot further out of step with what the caller thinks happened, in a way that only shows up as wrong values coming back out much later, not as an obvious crash near the actual mistake.

An alternative worth knowing: a separate count

The other standard way to resolve the same ambiguity is to keep an explicit count alongside head and tail, checking count == 0 for empty and count == capacity for full -- and using every slot, N out of N, rather than reserving one. It costs one extra integer of state that has to be kept exactly in step with every push and pop, in exchange for the full capacity. Both are legitimate; this exercise asks for the reserved-slot version specifically because it needs nothing beyond the two indices the function signature already gives you.

Cost

Both operations are O(1), using only the backing array and the two indices -- no allocation, no locking, which is the entire point of this shape of buffer between a producer and a consumer that must not block each other.
