RMS Voltage, RMS Current and Real Power in Fixed Point

Worked solution

This page contains the complete answer and explains why each part of it is there.

The idea

Three 64-bit accumulators, three divisions, two exact integer square roots.

/* Exact floor(sqrt(x)) by the digit-by-digit method. No floating point. */
static uint32_t isqrt64(uint64_t x)
{
    uint64_t result = 0;
    uint64_t bit = (uint64_t)1 << 62;

    while (bit > x) {
        bit >>= 2;
    }
    while (bit != 0) {
        if (x >= result + bit) {
            x -= result + bit;
            result = (result >> 1) + bit;
        } else {
            result >>= 1;
        }
        bit >>= 2;
    }
    return (uint32_t)result;
}

void rms_power(const int16_t *v, const int16_t *i, size_t n,
               uint32_t *vrms_out, uint32_t *irms_out, int32_t *p_out)
{
    uint64_t sum_vv = 0;
    uint64_t sum_ii = 0;
    int64_t sum_vi = 0;

    for (size_t k = 0; k < n; k++) {
        int64_t a = v[k];
        int64_t b = i[k];
        sum_vv += (uint64_t)(a * a);
        sum_ii += (uint64_t)(b * b);
        sum_vi += a * b;
    }

    *vrms_out = isqrt64(sum_vv / n);
    *irms_out = isqrt64(sum_ii / n);
    *p_out = (int32_t)(sum_vi / (int64_t)n);
}

The bit budget

QuantityLargest magnitudeBits
One sample3276816 (signed)
One square or product23031
Sum over 4096 samples24243
Mean23031 (so the result of the root is 16 bits)

The sum overflows int32_t and uint32_t long before 4096 samples. A 32-bit accumulator survives only 4 full-scale samples. That is the first hidden failure in the exercise, and the "longest buffer" test finds it.

Why the digit-by-digit root

It finds the answer one bit at a time, from the top, by testing whether the next bit fits. Each step is an add, a compare and a shift. It is exact, it needs no multiply or divide, and it runs a fixed 32 iterations. That makes it predictable on a core with no hardware divider.

A floating-point square root. A double has 53 bits of mantissa. A 43-bit sum is fine, but a 64-bit one is not, so the rounded result can be one too high. It also drags in a library and, on many parts, a software floating point routine. The "just below a perfect square" test is there to catch the one-too-high result.

The order of operations. isqrt(sum / n) and isqrt(sum) / sqrt(n) differ. The first is what the statement asks for. Taking the mean with rounding rather than flooring changes results too, where the mean is not a whole number.

The sign of the power

Real power P = mean(v * i). It is positive when current flows in the direction of the voltage, and negative when it flows back. For a battery, that is charging versus discharging. A meter that reports abs(P) or clamps at zero cannot tell import from export. The sum must stay signed all the way to the end.

Real, apparent and reactive

The three outputs give you apparent power S = Vrms * Irms, real power P, and from them the power factor P / S. When the current lags the voltage by a quarter cycle, the in-phase test gives P near zero, while S is not. That gap is reactive power.

Point to raise

This assumes a whole number of mains cycles in the buffer. With a partial cycle, the mean is biased. A real meter locks its sampling to the line frequency, or windows the data.
