Remove Duplicates From a Sorted Array

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

Compact the array so each distinct value appears once, in the first n slots, and return n. Whatever is left beyond index n - 1 is nobody's business — you do not have to blank it out.

The fact that makes it easy

The array is sorted. Equal values are therefore always adjacent. That means you never need to remember the values you have seen — a set, a hash table, a nested search — you only need to compare each element with the previous distinct one.

Two indices moving at different speeds

This is the standard read/write pair, and the names help:

  • read visits every element, one after another. It never goes backwards and never skips.
  • write marks where the next kept value goes. It only advances when you actually keep something, so it lags behind — and when the loop ends it is the count.

The invariant to hold in your head: everything below index write is already the correct, deduplicated prefix.

Because write can never outrun read, copying values[read] into values[write] can only ever overwrite a slot that has already been read. That is why compacting in place is safe and needs no scratch array.

What is the test?

"Is this element the same as the last one I kept?" Note the wording — the last one you kept, which lives at values[write - 1]. Comparing with values[read - 1] also works on sorted input, since duplicates are adjacent, but the first form is the one that keeps working if the problem changes.

Where do the indices start?

The first element is always kept — there is nothing before it to duplicate. So both indices can start at 1 with the answer already "at least one". That does mean the empty array must be dealt with first, because "at least one" is false when there are no elements at all.

Still stuck? A bigger nudge 
if (count <= 0) {
    return 0;
}

int write = 1;                       /* values[0] is always kept */
for (int read = 1; read < count; read++) {
    if (/* values[read] differs from the last kept value */) {
        values[write] = values[read];
        write++;
    }
}
return write;

One comparison to fill in. When the element is a duplicate you do nothing at all — no else, no shuffling down. Deleting in place is really just declining to copy.

Check yourself before you press Go

  • Empty array → 0, and no read through values (it may be NULL).
  • Single element → 1, array unchanged.
  • 7 7 7 7 7 → 1, and values[0] is 7.
  • All distinct → the count is unchanged and nothing has moved.
  • Did you allocate anything? You should not have.
