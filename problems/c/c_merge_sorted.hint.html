Merge Two Sorted Arrays

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

All count_a + count_b values, in ascending order, written into out. The caller has already sized out correctly, so there is nothing to allocate and nothing to return.

The insight

Both inputs are already sorted, and that is worth more than it first looks. The smallest value overall must be at the front of one array or the other — there is nowhere else it could be hiding. Take it, advance past it, and the same is true of what remains.

So: two positions, one in each array. Compare the two front elements, copy the smaller, advance that array's position only. Repeat.

a:  1  4  9        i ──►
b:  2  3  4  8     j ──►
out:                       take 1 (a) ─► i moves
     1                     take 2 (b) ─► j moves
     1  2                  take 3 (b) ─► j moves
     1  2  3               take 4 — from which one?

Three loops, and two of them are trivial

The comparison loop can only run while both arrays still have elements. As soon as one is exhausted there is nothing left to compare against, and the remainder of the other array is already in order — so it is copied across unchanged.

You cannot know in advance which one runs out first, so you write both drain loops and one of them does nothing.

Details that will cost you a test case

  • Check counts, not pointers. An empty array's pointer may be NULL. i < count_a must be tested before a[i] is read — which the loop conditions do for you, provided you never read outside them.
  • Both arrays may be empty. All three loops do nothing and out is untouched. That is correct: zero values written.
  • Duplicates are ordinary. Equal values across the two arrays are not a special case — but see below.
  • One output index. out is written strictly front to back, so a single k that only ever increments is all you need. Do not try to derive it from i + j… actually, you can, since every step advances exactly one of them. Either works; one variable is clearer.

Which array wins a tie? Use <= rather than < so that when the fronts are equal you take from a. Either choice produces correctly sorted output here, but preferring the first array is what makes a merge stable, and stability is the whole reason merge sort is worth having.

Still stuck? A bigger nudge 
int i = 0, j = 0, k = 0;

while (i < count_a && j < count_b) {
    /* copy the smaller front element into out[k++],
       advancing i or j -- exactly one of them */
}
while (i < count_a) {
    out[k++] = a[i++];
}
while (j < count_b) {
    out[k++] = b[j++];
}

The two drain loops are the easy part; write them first and the main loop has less to worry about.

Check yourself before you press Go

  • Both empty → nothing written, no crash.
  • First empty → the whole of b appears.
  • Second empty → the whole of a appears.
  • 1 2 and 8 9 → 1 2 8 9: the first array empties before the second is touched at all.
  • Equal values in both arrays all survive — merging keeps duplicates, it does not remove them.
