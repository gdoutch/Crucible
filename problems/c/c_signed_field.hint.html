Extract a Signed Sensor Reading

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

Start exactly like Extract a Register Field — shift the field down, mask it to width bits. That gets you an unsigned number in the range 0 to 2^width - 1. The new part is turning that into the signed value it actually represents: if the field's top bit is set, the number it encodes is negative, and you have one more step to get there.

Two's complement, backed out by hand

A width-bit two's-complement value in the top half of its range — top bit set — represents field - 2^width. Check it against a small example: 4 bits, field 0b1111 (15 as a plain unsigned number). 15 - 2^4 = 15 - 16 = -1, which is the everyday fact that "all ones" is -1 in two's complement, at any width.

So: extract the field as before, then — only if its own top bit is set — subtract 2^width from it.

The trap the problem is built around

"The field's own top bit" is bit width - 1 of the extracted, masked field — not bit 31 of reg, and not whatever bit happened to catch your eye. A register carrying a 12-bit reading has 20 other bits doing something else entirely, and none of them says anything about whether this field is negative.

Two of the fixed tests are built to expose exactly this: the same status flags surround a positive field in one case and a negative field in the other, with the register's own bit 31 set in one of them and clear in the other — deliberately not lined up with which field is actually negative. If your sign test looks anywhere in the register other than bit width - 1 of the masked field, one of those two comes back wrong.

The other trap, carried over

width can still be 32, and the mask formula needs the same special case it needed in the other two register problems — 1u << 32 is undefined behaviour.

Still stuck? A bigger nudge 
unsigned int mask = /* the width == 32 formula */;
unsigned int field = (reg >> start) & mask;
unsigned int sign_bit = 1u << (width - 1);

if (field & sign_bit) {
    /* field is in the negative half of its range -- pull it down */
    field -= /* 2 to the power width, as an unsigned int */;
}
return (int)field;

Everything stays unsigned int until the very last line. The cast to int at the end is where the bit pattern turns into the negative number it represents.

Check yourself before you press Go

  • extract_signed_field(0xFFF, 0, 12) → -1.
  • extract_signed_field(0x800, 0, 12) → -2048, the most negative 12-bit value.
  • extract_signed_field(0x7FF, 0, 12) → 2047, the most positive.
  • A field whose own top bit is 0 is positive, full stop — no matter what bit 31 of the register happens to be.
