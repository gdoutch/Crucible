Rotate an Array Left

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

1 2 3 4 5 rotated left by 2 becomes 3 4 5 1 2. The first shift elements go to the back; everything else slides down to fill the space. In place, in the caller's array.

Deal with shift before you deal with the array

Two facts about the parameter, and they interact:

  • shift may be larger than count. Rotating five elements by 7 is the same as rotating by 2, because a rotation by exactly count is the identity. So reduce it: shift %= count.
  • count may be zero.

Put those in the wrong order and you have written shift % 0. Integer division by zero in C is undefined behaviour, and on x86 it is a hardware fault — the process dies with SIGFPE, and Crucible reports the empty array case as a crash rather than a wrong answer.

Check the count first. Always.

After the reduction, shift == 0 means there is nothing to do — which covers both "asked for zero" and "asked for a whole number of full turns".

Now the rotation itself

The obvious approach copies the first shift elements into a temporary buffer, slides the rest down, and copies the temporary back. It works, and it needs O(shift) extra memory and a malloc that can fail.

There is a much nicer way, and it is worth the two minutes it takes to see why it works. Three reversals.

start          1 2 3 | 4 5        shift = 3
reverse [0, shift)     3 2 1 | 4 5
reverse [shift, end)   3 2 1 | 5 4
reverse the whole      4 5 | 1 2 3

Check it: 1 2 3 4 5 rotated left by 3 is indeed 4 5 1 2 3. Try it on paper with a different shift before you believe it.

The reason it works: reversing a block twice restores its order, and the final whole-array reversal reverses each block a second time while also swapping the two blocks' positions. Order restored, places exchanged — which is exactly what a rotation is.

The helper you will want

Write a small reverse_range(int *values, int from, int to) that swaps inwards between two inclusive indices, then call it three times. Mark it static — it is private to your translation unit, and it keeps the name out of the link.

Still stuck? A bigger nudge 
static void reverse_range(int *values, int from, int to)
{
    while (from < to) {
        /* swap values[from] and values[to], then move both inwards */
    }
}

void rotate_left(int *values, int count, int shift)
{
    if (count <= 0) {
        return;                      /* before the modulo! */
    }
    shift %= count;
    if (shift == 0) {
        return;
    }

    reverse_range(values, 0, shift - 1);
    reverse_range(values, shift, count - 1);
    reverse_range(values, 0, count - 1);
}

All three index pairs are inclusive, which is why they end in - 1. Being consistent about that is most of the battle.

Check yourself before you press Go

  • count == 0 → returns immediately, no division, no crash.
  • shift == 0 → array unchanged.
  • shift == count → array unchanged.
  • shift > count → same as shift % count.
  • Single element, any shift → unchanged.
