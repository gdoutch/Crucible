Setpoint Lease With a Safe Ramp-Down

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

Where to start

  • Elapsed time first. Everything else is built on now - last, so get the wrap right there and nowhere else.
  • There are three regions: valid, ramping, finished. Draw them on a line and mark the boundaries. <= and >= are in the statement for a reason.
  • The ramp is a straight line from setpoint at over = 0 to 0 at over = ramp_ms. Work out the value at the halfway point by hand.
  • Size the intermediate product. Largest setpoint times the largest remaining ramp: how many bits?
Still stuck?

The finished region returns before you divide, so a zero ramp_ms never reaches the division. Check that this is true for your ordering of the tests.

Before you run it

Read the test names in the app. Each one is a sentence about a case you might have missed. If you can predict the output of every one by hand, your design is probably right.
