Slew-Rate Limit a Demand Signal

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

How far the output is allowed to move this step, capped at max_step, toward wherever target currently is. If the target is close enough that a full step would overshoot it, land on it exactly instead.

The shape of it

int delta = target - previous_output;
/* clamp delta to [-max_step, max_step] */
return previous_output + delta;

Watch out

  • max_step is a magnitude, not a one-sided limit. A target below previous_output needs exactly the same clamping as one above it -- clamp delta on both sides, to [-max_step, max_step], not just capped at +max_step on the assumption the output only ever needs to rise.
  • Once the gap to the target is smaller than max_step, the clamp should not fire at all -- the output reaches the target exactly and then holds there on every following call with the same target, rather than creeping forever or stopping one step short.

Check yourself before you press Go

  • Starting at 0 with max_step = 10, a target of 100 gives 10, then 20, then 30, and so on.
  • From 50 with max_step = 5, a target of 0 gives 45, then 40, moving down just as readily as the example above moves up.
  • A target only 3 away with max_step = 100 is reached in one call, and stays there.
