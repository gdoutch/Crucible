Linear Interpolation Over a Calibration Table

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

A calibration table is a handful of (x, y) points. Given an x that falls between two of them, walk the straight line connecting those two points and read off the y at that x. Given an x outside the table entirely, hold the nearest edge instead of guessing past it.

The three cases, in order

  1. x <= xs[0] — clamp to ys[0].
  2. x >= xs[n - 1] — clamp to ys[n - 1].
  3. Otherwise, find consecutive breakpoints xs[i] and xs[i + 1] with xs[i] <= x <= xs[i + 1], and interpolate between them.

The interpolation itself is one line once you have the right interval:

ys[i] + (ys[i+1] - ys[i]) * (x - xs[i]) / (xs[i+1] - xs[i])

The trap the problem is built around

Look at the middle of that line: (ys[i+1] - ys[i]) * (x - xs[i]) is a multiplication done before the division that would otherwise keep it small. If both differences are a few tens of thousands — entirely realistic for a calibration table spanning a wide sensor range — their product is in the billions, past what a 32-bit int holds. One of the fixed tests is built exactly to this shape: a two-point table running `0` to `100000` on both axes, queried in the middle.

The fix is not a cleverer formula, just a wider type for the multiply: compute the product in a 64-bit type, then divide, then bring the result back down to int for the return.

Watch out, beyond the overflow

  • The division truncates toward zero, the way C's / always does on integers. Do not try to round it — one of the fixed tests exists specifically to check the answer is the truncated value, not the nearest one.
  • A table can have more than two breakpoints. Scan for the right interval rather than assuming xs[0]/xs[1] is always it.

Check yourself before you press Go

  • A table mapping 0,10,20 to 0,100,300, queried at 15, is 200 — halfway between 100 and 300.
  • Queried below 0 or above 20, it clamps rather than extrapolating.
  • A table spanning 0 to 100000 on both axes, queried in the middle, does not silently come back wrong or negative.
