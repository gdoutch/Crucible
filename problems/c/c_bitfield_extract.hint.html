Extract a Register Field

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

A slice of bits out of the middle of a 32-bit word, moved down so it reads as an ordinary number starting at bit 0. Two things describe the slice: start, where it begins, and width, how many bits it covers.

The two operators that do the work

  • reg >> start — slides the field down so its lowest bit lands on bit 0. Everything below start falls off the bottom, which is exactly where you want it to go.
  • & mask — clears everything above the field, where mask is width ones in a row: 0b1 for a 1-bit field, 0b1111 for a 4-bit field, and so on.

The standard way to build that mask is (1u << width) - 1u — shift a single 1 bit up past the top of the field, then subtract one so every bit below it turns on. Try it on paper for width = 4: 1 << 4 is 0b10000, minus one is 0b01111.

The trap the problem is built around

Try that same formula with width = 32. 1u << 32 is shifting a 32-bit type by its own bit width, which the C standard flatly does not define. It is not "the biggest value the type can hold" or anything else predictable — on the compiler this app builds with, it comes back as if you had written 1u << 0, because the hardware shift instruction only looks at the bottom few bits of the shift amount. That makes the mask 1u - 1u, which is 0. Every bit of the register you were trying to read gets masked away, and extract_field(0xFFFFFFFF, 0, 32) comes back 0 instead of the whole value.

One of the fixed test cases is exactly this: the whole register, width 32. If every other case passes and that one comes back 0, this is why.

Still stuck? A bigger nudge

Give width == 32 its own line rather than trying to make one formula cover both cases:

unsigned int mask;
if (width == 32) {
    mask = 0xFFFFFFFFu;
} else {
    mask = (1u << width) - 1u;
}

A conditional expression does the same thing in one line if you would rather:

unsigned int mask = (width == 32) ? 0xFFFFFFFFu : (1u << width) - 1u;

Either way, once mask is right the rest of the function is one line: shift, then mask.

Check yourself before you press Go

  • extract_field(0xF0, 4, 4) → 0xF — a field in the middle.
  • extract_field(0x80000000, 31, 1) → 1 — the highest legal start.
  • extract_field(0xFFFFFFFF, 0, 32) → the whole value, not 0.
