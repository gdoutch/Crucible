Single-Producer/Single-Consumer Ring Buffer

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

Two indices, head (where the next push writes) and tail (where the next pop reads), both wrapping around a fixed array with %. That part is routine. The actual problem is a question: given only head and tail, how do you tell a full buffer from an empty one, when both can leave head == tail?

The convention this exercise uses

Leave one slot permanently unused. A buffer of capacity N holds at most N - 1 items. In exchange:

  • head == tail means empty, always.
  • (head + 1) % capacity == tail means full, always — that is the state one push away from making head collide with tail, so the push that would cause the collision is the one that gets rejected instead.

No separate counter, and no ambiguity, at the cost of one slot of capacity you were never going to get to use anyway.

The trap the problem is built around

It is tempting to think a buffer sized for N items should hold N items. With this convention it cannot — the moment it held N, head would equal tail again, indistinguishable from empty. One of the fixed tests pushes into a capacity-4 buffer four times in a row: the first three succeed, and the fourth must report full, not succeed. If your code lets all four through, it has room for N items and no way left to tell full from empty — the two states have become the same head/tail pair.

Watch out, beyond the boundary

  • In ring_push, write to the current *head before advancing it. In ring_pop, read from the current *tail before advancing it. Advance first and the very first push or pop touches the wrong slot.
  • capacity is not guaranteed to be a power of two — use %, not a bitmask.

Check yourself before you press Go

  • A fresh buffer of capacity 3 accepts two pushes and rejects a third.
  • Popping an empty buffer reports empty and does not touch *value_out.
  • Push, pop, push, pop, repeated many times, never runs out of room — the buffer recycles the slot each pop frees.
