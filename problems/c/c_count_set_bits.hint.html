Count the Set Bits

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

How many of the 32 bits in an unsigned int are 1. This is the population count — popcount in most instruction sets.

The straightforward approach

Two operators do all the work:

  • value & 1u — the lowest bit, as a 0 or a 1. Add it straight into your counter; there is no need for an if.
  • value >>= 1 — shift everything down one place, so the next bit up becomes the lowest.

Repeat until there is nothing left. Stopping at value != 0 is natural; looping exactly 32 times is also correct and slightly simpler to reason about.

The trap the problem is built around

The parameter is unsigned int, and the tests will punish you for quietly turning it back into a signed one.

Copy it into an int, or write your loop variable as int, and the value 4294967295 arrives as -1. Right-shifting a negative signed value is implementation defined: on every mainstream compiler it shifts the sign bit in from the top, so -1 >> 1 is -1 again, forever. Your while (value != 0) never ends and the test case reports TIMEOUT.

Two of the four fixed cases — every bit set and the top bit alone — exist purely to catch this. If they hang or come back wrong while the small cases pass, look for a missing unsigned.

Then, when it works, make it clever

There is a well-known identity worth knowing:

value & (value - 1)

Subtracting one from a number flips its lowest set bit to 0 and turns every zero below it into a 1. AND-ing that with the original therefore clears exactly the lowest set bit and changes nothing else. Work it through on paper for value = 0b10110000 and you will see it.

That gives a loop that runs once per bit that is actually set, rather than once per bit position — so a value with two bits set takes two iterations instead of 32. Same answer, and the loop reads as "keep removing a bit until there are none left".

Still stuck? A bigger nudge

The shift version:

int count = 0;
while (value != 0) {
    count += value & 1u;
    value >>= 1;
}
return count;

The clear-lowest-bit version has the same skeleton, but the body is one statement plus count++. Both are accepted; only one of them looks like it was written by someone who has done this before.

Check yourself before you press Go

  • 0 → 0.
  • 1 → 1.
  • 4294967295 → 32, promptly.
  • 2147483648 (bit 31 alone) → 1, promptly.
