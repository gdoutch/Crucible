Decode a Modbus RTU Read Response

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

Where to start

  • Order is the specification. The table fixes which error wins when a frame is wrong in two ways. A frame with a bad CRC and the wrong address is -2.
  • Write the CRC as a small helper over (data, len). Test it on its own against a frame you can check by hand.
  • Two bytes of CRC are at the end, low byte first. Build the 16-bit value from them before comparing.
  • Think about which indexes each check is allowed to touch. Check 1 is what makes frame[len - 2] safe.
Still stuck?

Build the value in uint32_t, shifting each byte in. Convert to int32_t only at the end. Shifting a uint8_t left by 24 promotes it to int, which can overflow. Cast it first.

Before you run it

Read the test names in the app. Each one is a sentence about a case you might have missed. If you can predict the output of every one by hand, your design is probably right.
