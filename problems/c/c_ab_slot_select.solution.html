Choose a Boot Slot (A/B Update with Anti-Rollback)

Worked solution

This page contains the complete answer and explains why each part of it is there.

The idea

One helper to decide eligibility. One function to compare the eligible.

static int bootable(const struct slot_header *s, uint32_t min_security_version)
{
    return s->valid != 0
        && s->security_version >= min_security_version
        && (s->confirmed != 0 || s->trial_remaining > 0u);
}

int select_slot(const struct slot_header *a, const struct slot_header *b,
                uint32_t min_security_version)
{
    int a_ok = bootable(a, min_security_version);
    int b_ok = bootable(b, min_security_version);

    if (a_ok && b_ok) {
        return (b->version > a->version) ? 1 : 0;
    }
    if (a_ok) {
        return 0;
    }
    if (b_ok) {
        return 1;
    }
    return -1;
}

The tie-break

b->version > a->version picks B only if it is strictly newer. Equal versions fall through to A. That gives a deterministic answer, which matters in a bootloader: the same inputs must always boot the same slot.

How the rollback works

StageSlot B stateResult
Just installedvalid, trial 3, unconfirmedBoot B
Boots, fails, resets (x3)trial 2, 1, 0Boot B each time
Fourth resettrial 0, unconfirmedNot bootable. Boot A
Boots and passes its self-testconfirmedBoot B from now on

The trial counter is the whole recovery mechanism. A bootloader decrements it on each boot. The application confirms the image once it has proved it works. A bad image can only burn through its counter. It cannot lock the device.

Choosing by version before checking bootability. "Take the higher version, and fall back if it fails" is two ideas tangled together. It breaks when the newest image is the one that cannot boot. Decide eligibility first, then choose from what is left.

Applying the anti-rollback floor only to the new image. The floor is about every image. The old, confirmed one may be exactly the vulnerable version the floor exists to forbid. If both fail the floor, the right answer is -1, and the device must stop in recovery. It should not boot the insecure image.

Point to raise

The floor in fuses is raised only after the new image is confirmed. Raise it when the update is merely installed, and a failed update can no longer roll back, because the old image is now below the floor.
