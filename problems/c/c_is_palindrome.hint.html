Palindrome Check

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

1 or 0: does the string read the same both ways once you ignore case and everything that is not a letter or a digit? So A man, a plan, a canal: Panama counts.

The tempting approach, and the better one

You could build a cleaned-up copy — strip the punctuation, lower-case everything — and then compare it with its reverse. That works. It also needs a buffer, and a decision about how big, and a plan for what happens if the input is longer than you guessed.

The alternative does the cleaning as it goes: two indices walking inwards, each one skipping over anything it should be ignoring. No copy, no allocation, and the empty string needs no thought.

Two pointers, three possible moves

At every step, look at the character on the left and the character on the right. Exactly one of these applies, and the order you test them in matters:

  1. The left character is not alphanumeric → advance the left index only and start again. Do not compare yet.
  2. The right character is not alphanumeric → retreat the right index only and start again.
  3. Both are alphanumeric → now a comparison is meaningful. If they differ (case-insensitively) the answer is 0 immediately. If they match, move both inwards.

If the indices meet or cross without ever finding a mismatch, it is a palindrome.

Do not skip both sides in one step. Advancing the left index and retreating the right one when only the left character is punctuation throws away a character on the right that was never examined. Handle one side per iteration — that is why the list above is an if / else if / else if chain rather than three independent ifs.

Details that will cost you a test case

  • Where does the right index start? If you use strlen(s) directly, that is the index of the terminator — so compare s[j - 1] rather than s[j], or start at strlen(s) - 1 and worry about the empty string.
  • size_t is unsigned. strlen("") - 1 is not -1; it is a colossal positive number. Same trap as Reverse a String In Place.
  • Cast for <ctype.h>. isalnum((unsigned char)s[i]) and tolower((unsigned char)s[i]). Passing a plain char is undefined behaviour for bytes above 127.
  • The empty string is a palindrome — the loop simply never runs.
Still stuck? A bigger nudge 
size_t i = 0;
size_t j = strlen(s);        /* one PAST the last character */

while (i < j) {
    if (/* s[i] is not alphanumeric */) {
        i++;
    } else if (/* s[j - 1] is not alphanumeric */) {
        j--;
    } else if (/* the two differ, ignoring case */) {
        return 0;
    } else {
        i++;
        j--;
    }
}
return 1;

Keeping j one past the end means strlen("") == 0 needs no special case: 0 < 0 is false and you return 1. The cost is remembering the - 1 every time you read through j.

Check yourself before you press Go

  • Empty string → 1.
  • Single character → 1.
  • A man, a plan, a canal: Panama → 1.
  • ab → 0; aba → 1.
  • !!! — nothing but punctuation → 1, and no infinite loop.
