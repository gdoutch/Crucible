FizzBuzz

Worked solution

This page contains the complete answer and explains why each part of it is there.

The idea

Count from 1 to n and, for each number, pick exactly one of four things to print. The only real content is the order of the tests: the overlapping case has to be decided before the cases it overlaps with.

The code

#include <stdio.h>

void fizzbuzz(int n)
{
    for (int i = 1; i <= n; i++) {
        if (i % 15 == 0) {
            printf("FizzBuzz\n");
        } else if (i % 3 == 0) {
            printf("Fizz\n");
        } else if (i % 5 == 0) {
            printf("Buzz\n");
        } else {
            printf("%d\n", i);
        }
    }
}

Why % 15 works

A number divisible by both 3 and 5 is divisible by their least common multiple. 3 and 5 are coprime, so that is simply 3 × 5 = 15. Writing i % 3 == 0 && i % 5 == 0 is equally correct and arguably states the intent more plainly; % 15 is the more common idiom and one modulo cheaper.

Do not generalise the shortcut carelessly. For 4 and 6 the equivalent constant is 12, not 24 — the LCM, not the product. It only collapses to the product when the two divisors share no factors.

Why the order is forced

The else if chain evaluates top to bottom and stops at the first match, so each arm implicitly carries "and nothing above matched". Reversing the first two arms breaks every multiple of 15:

iCorrectWith % 3 tested first
3FizzFizz
5BuzzBuzz
15FizzBuzzFizz ✗
30FizzBuzzFizz ✗

If a randomised case gives you an n below 15, that bug hides completely — which is precisely why Crucible reshuffles the data. Press Ctrl+R and the bug surfaces the first time n reaches 15.

The composition alternative

If the ordering rule feels like something you have to remember rather than something the code enforces, build the answer instead of choosing it:

for (int i = 1; i <= n; i++) {
    char line[16] = "";
    if (i % 3 == 0) { strcat(line, "Fizz"); }
    if (i % 5 == 0) { strcat(line, "Buzz"); }
    if (line[0] == '\0') {
        printf("%d\n", i);
    } else {
        printf("%s\n", line);
    }
}

Two independent tests, no precedence, and the FizzBuzz case is produced rather than special-cased. It also extends to a third rule without touching the existing ones — with the else if chain, adding "multiples of 7 print Bazz" means writing arms for 21, 35 and 105 as well. That is the interesting property of this version, and the reason FizzBuzz is still worth writing.

The n = 0 case

The loop condition 1 <= 0 is false immediately, so nothing is printed and the function returns. Same for any negative n. No guard needed — but check what your code does, because a do…while or a loop written from 0 to n - 1 with an offset can easily emit one line here.

The expected output for that case is the empty string. Crucible strips trailing blank lines before comparing, so a stray final \n would not fail you — but an actual printed line would.

Cost

O(n) time, O(1) space. The printf calls dominate everything else; if this ever mattered you would build a buffer and write once, and it has never mattered.

Wrong turns worth recognising

Off-by-one at the top. i < n instead of i <= n silently drops the last line. With n = 15 that is the FizzBuzz line specifically — two bugs that mask each other on exactly one input.

Printing with puts and then adding \n. puts appends a newline of its own, so puts("Fizz\n") emits a blank line after every Fizz. Crucible reports this as "expected 15 line(s), got 20".
