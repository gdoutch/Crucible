Sort an Array In Place

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

Ascending order, in the caller's own array, with no return value. And written by hand — qsort passes the tests and skips the exercise.

Think of a hand of cards

Insertion sort is the way most people sort a dealt hand without being taught to. The cards on the left are already in order; you pick up the next one and slide it left past everything bigger until it is in the right place.

So the invariant is: after processing index i, the elements values[0..i] are sorted among themselves. They are not in their final positions — later elements can still land among them — but they are in order relative to each other. Start with i = 0, which is trivially sorted, and grow the sorted region one element at a time.

The inner loop is a shift, not a swap

Here is where people go wrong. To insert a value you need a gap for it, and you make the gap by moving the bigger elements one place right — working from the right-hand end of the sorted region backwards, so nothing is overwritten before it has been copied.

That means you must save the value you are inserting before you start shifting. Its slot is the first one to be overwritten.

sorted region        the value being placed
┌───────────────┐   ┌───┐
│ 2   5   9     │   │ 4 │   key = 4, saved out of the way
└───────────────┘   └───┘
      9 moves right ──────►     2   5   _   9
      5 moves right ──────►     2   _   5   9
      2 is not bigger; stop.    2   4   5   9

The inner loop's two exit conditions

Stop shifting when either:

  • you find an element that is not greater than the value you are placing — everything to its left is smaller still, so the gap is where the value belongs; or
  • you run off the front of the array, meaning the value is smaller than everything and belongs at index 0.

Order those two tests carefully. while (values[j] > key && j >= 0) reads values[-1] before it checks whether j is still valid. C's && evaluates left to right and short-circuits, so the bounds test has to come first.

Details

  • The outer loop starts at 1, not 0 — a one-element region is already sorted.
  • Use >, not >=, in the shift condition. With >= equal elements are shuffled past each other for no reason, which costs time and loses stability.
  • count may be 0 with values == NULL, and may be 1. Check that your loops simply do not run rather than adding guards.
Still stuck? A bigger nudge 
for (int i = 1; i < count; i++) {
    int key = values[i];          /* save it before the slot is clobbered */
    int j = i - 1;

    while (/* j is still valid AND values[j] is bigger than key */) {
        values[j + 1] = values[j];    /* shift right */
        j--;
    }

    values[j + 1] = key;          /* the gap is at j + 1, not j */
}

The j + 1 at the end catches people. When the loop stops, j points at the element that should stay to the left of the key (or at -1), so the gap is the slot after it.
