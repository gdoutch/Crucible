Greatest Common Divisor

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

The largest integer that divides both a and b exactly. Both are zero or positive.

The obvious way, and why not

You could count down from min(a, b) and return the first value that divides both. That is correct, and it will pass. It also takes up to two billion iterations for a pair of large primes, and it needs a special case for zero because x % 0 is undefined — a crash, not a wrong answer.

There is a two-thousand-year-old alternative that is three lines long.

Euclid's observation

Any number that divides both a and b also divides their remainder a % b. So the pair (a, b) and the pair (b, a % b) have exactly the same set of common divisors — and therefore the same greatest one.

That is a licence to shrink the problem. Replace the pair with the smaller pair, over and over. The second number strictly decreases every step, so you must eventually reach zero, and when b is 0 the answer is sitting in a: every number divides zero, so the greatest common divisor of a and 0 is a.

Try it by hand on (48, 18) before you write anything. You should reach the answer in four steps.

Why the zero cases fall out for free

  • gcd(0, 18) — b is not zero, so one step runs: the pair becomes (18, 0 % 18) = (18, 0), and 18 is returned. The arguments swapping themselves round is a pleasant accident of the algorithm, not something you have to arrange.
  • gcd(0, 0) — the loop never runs at all and a comes back as 0, which is the answer the tests want.

So if you find yourself writing if (a == 0) return b;, delete it and check whether the loop already did that for you.

Still stuck? A bigger nudge 
while (b != 0) {
    int remainder = /* the remainder of a divided by b */;
    a = b;
    b = remainder;
}
return a;

The temporary is needed because both assignments happen at once conceptually, but one at a time in C. Overwrite a first and the old value is gone before you compute the remainder from it.

Check yourself before you press Go

  • gcd(0, 0) → 0, and no division by zero on the way.
  • gcd(0, 18) → 18.
  • gcd(24, 24) → 24.
  • gcd(1, 97) → 1 — coprime numbers.
  • Does it terminate for every input? An infinite loop here shows up as a TIMEOUT, not a wrong answer.
