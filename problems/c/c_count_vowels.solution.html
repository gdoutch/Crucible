Count the Vowels

Worked solution

This page contains the complete answer and explains why each part of it is there.

The idea

One pass, one counter. The only real content is the membership test, and the trick to keeping that readable is to fold the case first so the test has five arms instead of ten.

The code

#include <ctype.h>

int count_vowels(const char *s)
{
    int count = 0;
    for (; *s != '\0'; s++) {
        switch (tolower((unsigned char)*s)) {
        case 'a':
        case 'e':
        case 'i':
        case 'o':
        case 'u':
            count++;
            break;
        default:
            break;
        }
    }
    return count;
}

The switch uses deliberate fall-through: case 'a': has no body, so control falls to the next label, and all five converge on the single count++. That is the one place fall-through is uncontroversial — grouping labels that share an action — and a compiler warning about implicit fall-through will not fire on empty cases.

An if chain is exactly as good:

int c = tolower((unsigned char)*s);
if (c == 'a' || c == 'e' || c == 'i' || c == 'o' || c == 'u') {
    count++;
}

So is strchr("aeiou", c) != NULL, with one caveat worth knowing: strchr also matches the terminating '\0' of its first argument, so if c could ever be zero it would report a false match. Here it cannot, because the loop has already stopped at the terminator — but that is a real bug in other people's code.

The cast is the point of the problem

tolower((unsigned char)*s) — not tolower(*s).

Every function in <ctype.h> takes an int, and the standard says the value must either be EOF or be representable as an unsigned char. Plain char is signed on x86 and ARM64 alike, so the byte 0xC3 — the first byte of é in UTF-8 — arrives as -61. Passing that is undefined behaviour. In a typical implementation tolower indexes a lookup table with the value, so a negative argument reads memory before the start of the table.

The cast to unsigned char reinterprets the byte as 0..255, and the implicit promotion to int then keeps it positive. It costs nothing at runtime and it is correct everywhere.

You can also skip <ctype.h> entirely and test both cases by hand — *s == 'a' || *s == 'A' || .... Ten comparisons instead of five, but no locale and no cast to get wrong. Either answer is a good answer; the bad answer is tolower(*s) unqualified.

Why the fixed cases are the ones they are

CaseWhat it is defending
empty string *s is '\0' on the first test, the body never runs, 0 comes back. A do…while here would examine the terminator once before checking anything.
no vowels (rhythm) y is not a vowel in this problem. It is the classic "sometimes y" ambiguity, pinned down by a test so it cannot be argued about.

Cost

O(n) in the length of the string, O(1) space. Note that walking the pointer avoids the trap of writing for (size_t i = 0; i < strlen(s); i++), which re-measures the string on every iteration and turns a linear loop into a quadratic one. Compilers can sometimes hoist that call out, but only when they can prove the string is not modified — do not rely on it.

Wrong turns worth recognising

Counting bytes, not characters. This function counts ASCII vowels. Accented vowels in UTF-8 are multi-byte sequences and will not match, which is the right behaviour for this problem and the wrong behaviour for a real text processor. Knowing which one you have written is the skill.

Modifying the string. The parameter is const char *. Calling something like *s = tolower(*s) to normalise in place will not compile, and that is the const doing its job — the caller's buffer is not yours to rewrite.
