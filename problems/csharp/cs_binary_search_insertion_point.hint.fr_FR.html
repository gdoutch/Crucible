Une recherche binaire ordinaire, avec un changement à la fin

int low = 0, high = sortedValues.Length - 1;
while (low <= high) {
    int mid = low + (high - low) / 2;
    if (sortedValues[mid] == target) return mid;
    if (sortedValues[mid] < target) low = mid + 1;
    else high = mid - 1;
}
// non trouvé : low se trouve maintenant exactement au point d'insertion
return ~low;

Pourquoi low, spécifiquement, est le point d'insertion

Suivez ce que signifient low et high à chaque étape : tout ce qui est strictement avant low est connu pour être plus petit que target, et tout ce qui est strictement après high est connu pour être plus grand. La boucle ne s'arrête qu'une fois que low > high -- à ce moment, low est devenu le premier indice dont la valeur serait plus grande que target, ce qui est exactement là où target doit se trouver.

La ligne qu'il est facile d'inverser

~low, pas -low. ~5 vaut -6 ; -5 vaut -5. Si low finit par valoir 0 (la cible appartient tout au début), -0 vaut simplement 0 -- indiscernable de « trouvé à l'indice 0 » -- alors que ~0 vaut -1, sans ambiguïté. C'est le complément binaire qui rend l'indice 0 représentable comme un résultat négatif « non trouvé, insérer ici ».
