Min, Max and Sum as a Value Tuple

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

public static (int Min, int Max, long Sum) Stats(int[] values)
{
    int min = values[0];
    int max = values[0];
    long sum = 0;

    foreach (int v in values)
    {
        if (v < min) { min = v; }
        if (v > max) { max = v; }
        sum += v;
    }

    return (min, max, sum);
}

Why sum is long from its very first assignment

sum += v runs once per element, and every one of those additions happens in whatever type sum was declared as. If that type is int, each addition is an int addition -- unchecked by default in C#, so it silently wraps rather than throwing -- and the overflow has already happened by the time a later cast to long would try to fix it. Declaring long sum = 0; up front means every one of those additions is a long addition from the start, with roughly nine quintillion of headroom rather than about two billion.

Why min and max start from values[0]

Seeding both from the array's own first element, rather than from int.MinValue/int.MaxValue, means the comparisons inside the loop only ever have to ask "is this element more extreme than anything seen so far" -- true for every element on an all-negative or all-positive array precisely because the starting point is itself a real element, not a sentinel that happens to already be more extreme than everything real the array could contain. The fixed tests for an all-negative and an all-positive array exist because seeding from int.MaxValue for min (or the reverse for max) happens to work by luck on an array that straddles zero, and only shows itself wrong on one that does not.

The tuple itself

return (min, max, sum); constructs the tuple positionally -- the names Min, Max and Sum from the return type are attached by the compiler based on position, not by matching a name written at the call site. A caller can then write var result = Stats(values); result.Min and get a genuinely named field, not an index into an anonymous array.

Cost

O(n) in the length of `values` -- one pass, three running values updated per element, no allocation.
