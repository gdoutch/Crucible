Aire totale via une interface

Solution détaillée

Cette page contient la réponse complète et explique pourquoi chaque partie s'y trouve.

Le code

public static double TotalArea(List<IShape> shapes)
{
    double total = 0;
    foreach (var shape in shapes)
    {
        total += shape.Area();
    }
    return total;
}

Pourquoi cela ne demande aucune connaissance de Circle ou Rectangle

shape.Area() est une répartition virtuelle à travers l'interface IShape : à l'exécution, l'appel atterrit sur l'implémentation réelle d'Area() du type concret, décidée par le type réel de l'objet, pas par le type au moment de la compilation de la variable shape (qui reste IShape tout au long de cette fonction). C'est précisément ce qui rend cette fonction correcte pour un type dont elle n'a jamais entendu parler -- une troisième implémentation cachée, disons, avec sa propre formule pour son propre Area() -- sans aucun changement nécessaire ici. Une fonction qui demande plutôt « est-ce un Circle ? est-ce un Rectangle ? » a réimplémenté à la main, et mal, la répartition propre de l'interface : elle ne reconnaît que les types dont quelqu'un s'est souvenu de vérifier l'existence, et la troisième forme non documentée d'un cas de test fixe expose exactement cette lacune.

Pourquoi une liste vide ne demande aucun cas particulier

total commence à 0, et foreach sur une liste vide n'exécute simplement jamais son corps -- la fonction retourne 0 sans vérification explicite, de la même façon qu'une somme sur zéro élément devrait toujours le faire.

Coût

O(n) dans le nombre de formes -- un appel virtuel à Area() par forme, aucune allocation.
