Valeur nullable ou repli

Solution détaillée

Cette page contient la réponse complète et explique pourquoi chaque partie s'y trouve.

Le code

public static int ValueOrDefault(int? value, int fallback)
{
    return value ?? fallback;
}

Pourquoi c'est toute la fonction

?? est défini exactement pour cette forme : son opérande de gauche est un type nullable (ou n'importe quel type référence), son opérande de droite est la valeur à produire si celui de gauche s'avère être null, et le résultat est le type non nullable sous-jacent -- un int, ici, pas un int?, parce qu'une fois l'opérateur exécuté il ne reste plus rien d'incertain. Écrire l'équivalent à la main :

return value.HasValue ? value.Value : fallback;

produit la même réponse, et mérite d'être reconnu comme la même idée en plus de mots -- ?? n'a pas inventé un nouveau comportement, il a nommé un motif suffisamment courant pour mériter son propre opérateur.

La version à éviter activement est value.Value utilisé directement, en supposant que « l'appelant n'enverrait pas null sans raison » -- l'un des cas de test fixes envoie exactement cela, et InvalidOperationException : Nullable object must have a value. n'est un résultat de test réussi sous aucune interprétation du contrat de cette fonction.

Coût

O(1) -- une seule comparaison et, au plus, une seule lecture de valeur.
