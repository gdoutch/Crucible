Balanced Brackets, Three Kinds

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

public static bool IsBalanced(string text)
{
    var closesFor = new Dictionary<char, char> { [')'] = '(', [']'] = '[', ['}'] = '{' };
    var stack = new Stack<char>();

    foreach (char c in text)
    {
        if (c == '(' || c == '[' || c == '{')
        {
            stack.Push(c);
        }
        else if (closesFor.ContainsKey(c))
        {
            if (stack.Count == 0 || stack.Pop() != closesFor[c])
            {
                return false;
            }
        }
    }
    return stack.Count == 0;
}

Why the empty-stack check comes first, in the same expression

stack.Count == 0 || stack.Pop() != closesFor[c] relies on || short-circuiting: when the stack is empty, the left side is true and Pop() is never called at all, so the InvalidOperationException it would otherwise throw never has a chance to. Writing the two checks as separate statements works too, as long as the empty check genuinely happens first and genuinely returns before reaching the Pop() call -- the risk with separating them is a refactor later moving one past the other without the ordering being obviously load-bearing the way it is when they share one short-circuited expression.

Why the final check is on the stack, not on anything seen while scanning

"(()" never encounters a closing bracket that disagrees with what is open -- there simply are not enough closing brackets to reach the point of disagreement. Nothing about scanning left to right ever notices that; the only place it shows up is that the stack still has an unclosed '(' on it once text runs out. That is exactly what return stack.Count == 0; is checking: not "did I ever see a mismatch", but "is there anything still waiting to be closed".

Cost

O(n) in the length of `text` -- each character is looked at once, and each bracket does at most one push or one pop.
