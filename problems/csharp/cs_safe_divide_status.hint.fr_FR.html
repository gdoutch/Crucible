Division avec deux modes d'échec distincts

Indice

Un coup de pouce dans la bonne direction. La réponse complète se trouve sur la page de la solution détaillée, donc rien ci-dessous ne la révèle.

Vérifiez les deux cas particuliers avant de diviser quoi que ce soit

if (b == 0) {
    return (DivideStatus.DivideByZero, 0);
}
if (a == int.MinValue && b == -1) {
    return (DivideStatus.Overflow, 0);
}
return (DivideStatus.Ok, a / b);

Pourquoi la seconde vérification ne peut pas être un bloc catch

Il est tentant de laisser a / b s'exécuter dans un try et de capturer ce qu'il lève -- mais au moment où l'exception a été levée, elle s'est déjà produite, à un coût, pour une entrée que cette fonction est précisément censée reconnaître et traiter *sans* jamais lever d'exception. Pire, capturer une simple OverflowException autour de la division et la signaler comme DivideByZero (en réutilisant le cas voisin qui semble erroné) rapporte une raison de l'échec qui n'a rien à voir avec ce qui s'est réellement passé. Vérifiez explicitement a == int.MinValue && b == -1, avant même que la division ne s'exécute.

Si vous n'êtes pas certain que la division entière vérifie le débordement sans condition en C# (contrairement à +/-/*, qui ne le font qu'à l'intérieur d'un bloc checked), c'est exactement le fait que cet exercice est construit pour vous faire confirmer par vous-même.
