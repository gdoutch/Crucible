Character Frequency Count

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

public static Dictionary<char, int> CountFrequencies(string text)
{
    var counts = new Dictionary<char, int>();
    foreach (char c in text)
    {
        counts[c] = counts.GetValueOrDefault(c) + 1;
    }
    return counts;
}

Why GetValueOrDefault needs no branch

counts.GetValueOrDefault(c) returns the stored value for c if there is one, and 0 -- the type's default -- if there is not, rather than throwing the way the plain indexer's getter does. 0 is exactly the right answer to "how many times has c been seen so far" on its first occurrence, which is what makes counts[c] = counts.GetValueOrDefault(c) + 1; correct whether this is the character's first appearance or its hundredth: the same one line handles both, because the starting point for "add one" is already right either way.

The version this replaces, counts[c]++, is not wrong in spirit -- it is exactly the operation being performed here -- it is wrong because the read half of that compound assignment goes through the indexer's plain getter, which throws KeyNotFoundException on a key that has never been written, rather than the more forgiving GetValueOrDefault.

Why the whole alphabet does not need pre-populating

An alternative fix -- initialise every character that might appear to 0 before the loop runs, so the plain indexer never meets a missing key -- works, but requires knowing the whole alphabet up front and pre-populating an entry for each one, most of which the input will never actually use. GetValueOrDefault sidesteps needing that alphabet at all: entries are created lazily, exactly for the characters that actually occur, which is also why an empty text correctly produces an empty dictionary rather than one full of zeros.

Cost

O(n) in the length of `text` -- one dictionary lookup and one write per character, both O(1) on average.
