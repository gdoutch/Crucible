Crucible · C# · difficile

Entrelacer deux séquences, paresseusement

Solution détaillée

Cette page contient la réponse complète et explique pourquoi chaque partie s'y trouve.

Le code

public static IEnumerable<int> Interleave(IEnumerable<int> a, IEnumerable<int> b)
{
    using var ea = a.GetEnumerator();
    using var eb = b.GetEnumerator();
    bool aHasMore = ea.MoveNext();
    bool bHasMore = eb.MoveNext();

    while (aHasMore || bHasMore)
    {
        if (aHasMore)
        {
            yield return ea.Current;
            aHasMore = ea.MoveNext();
        }
        if (bHasMore)
        {
            yield return eb.Current;
            bHasMore = eb.MoveNext();
        }
    }
}

Pourquoi deux drapeaux indépendants, pas une seule variable de boucle partagée

aHasMore et bHasMore sont suivis séparément parce que les deux séquences se terminent indépendamment -- l'une peut encore avoir mille éléments quand l'autre s'épuise après deux. Les fusionner en une seule condition « continuer » vérifiée avec && répond à une question différente de celle posée par cet exercice : cela arrête tout l'entrelacement dès que la séquence la plus courte est épuisée, en abandonnant tout ce qu'il reste dans la plus longue. Le || dans la condition de boucle, associé aux deux if indépendants à l'intérieur, est ce qui permet à chaque côté de continuer à contribuer exactement aussi longtemps qu'il lui reste quelque chose, sans dépendre de l'état de l'autre côté.

Pourquoi cela doit être GetEnumerator() et MoveNext(), pas deux boucles foreach

Une boucle foreach possède son énumérateur pour tout le corps de la boucle et ne peut pas rendre la main à un contexte extérieur en cours d'itération pour laisser une *autre* séquence avoir son tour -- il n'y a aucun moyen d'écrire « avancer a d'un cran, puis mettre en pause, puis avancer b d'un cran » en utilisant foreach sur l'une ou l'autre séquence seule. Sortir les énumérateurs à la main est ce qui rend « un pas de chacun, en alternance » exprimable : chaque appel à MoveNext() avance exactement un côté, exactement un élément, et l'état propre de la méthode (quel côté vient ensuite) vit dans les variables locales entre les appels -- ce qui est aussi précisément ce que la machine à états générée par le compilateur pour yield return existe pour préserver entre les pauses.

Pourquoi les énumérateurs sont enveloppés dans using

IEnumerator<T> étend IDisposable, et un appelant est libre d'arrêter d'énumérer le résultat entrelacé avant qu'il ne se termine complètement -- en ne prenant que les trois premiers éléments avec .Take(3), par exemple. using var ea = ...; garantit que le `Dispose()` d'ea (et d'eb) s'exécute quand l'itérateur lui-même est disposé, que cela se produise parce qu'il s'est terminé complètement ou parce qu'un appelant s'est arrêté en cours de route ; pour une simple séquence en mémoire comme une List<int>, cela n'a rien de réel à nettoyer, mais le même code entrelaçant deux séquences adossées à des fichiers ouverts ou des flux réseau perdrait une ressource par énumération abandonnée sans cela.

Coût

O(n + m) où n et m sont les longueurs des deux séquences -- chaque élément de chaque source est visité exactement une fois, et rien n'est mis en mémoire tampon : toute la séquence est produite paresseusement, un élément par MoveNext() sur le résultat.
