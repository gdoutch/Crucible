Binary Search With an Insertion-Point Convention

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

An ordinary binary search, with one change at the end

int low = 0, high = sortedValues.Length - 1;
while (low <= high) {
    int mid = low + (high - low) / 2;
    if (sortedValues[mid] == target) return mid;
    if (sortedValues[mid] < target) low = mid + 1;
    else high = mid - 1;
}
// not found: low is now sitting exactly at the insertion point
return ~low;

Why low, specifically, is the insertion point

Trace what low and high mean at every step: everything strictly before low is known to be smaller than target, and everything strictly after high is known to be larger. The loop only stops once low > high -- at which point low has become the first index whose value would be larger than target, which is exactly where target belongs.

The one line that is easy to get backwards

~low, not -low. ~5 is -6; -5 is -5. If low ever comes out to 0 (the target belongs at the very front), -0 is just 0 -- indistinguishable from "found at index 0" -- while ~0 is -1, unambiguous. The bitwise complement is what makes index 0 representable as a negative "not found, insert here" result at all.
