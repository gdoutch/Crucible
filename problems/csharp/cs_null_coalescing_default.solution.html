Nullable Value or Fallback

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

public static int ValueOrDefault(int? value, int fallback)
{
    return value ?? fallback;
}

Why this is the whole function

?? is defined for exactly this shape: its left operand is a nullable type (or any reference type), its right operand is the value to produce if the left one turns out to be null, and the result is the underlying non-nullable type -- an int, here, not an int?, because by the time the operator has run there is nothing left to be uncertain about. Writing the equivalent out by hand:

return value.HasValue ? value.Value : fallback;

produces the same answer, and is worth recognising as the same idea in more words -- ?? did not invent new behaviour, it named a pattern common enough to deserve its own operator.

The version to actively avoid is value.Value reached for directly, on the assumption that "the caller wouldn't send null for no reason" -- one of the fixed tests sends exactly that, and InvalidOperationException: Nullable object must have a value. is not a passing test result under any interpretation of this function's contract.

Cost

O(1) -- a single comparison and, at most, one value read.
