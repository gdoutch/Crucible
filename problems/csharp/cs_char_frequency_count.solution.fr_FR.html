Comptage de fréquence des caractères

Solution détaillée

Cette page contient la réponse complète et explique pourquoi chaque partie s'y trouve.

Le code

public static Dictionary<char, int> CountFrequencies(string text)
{
    var counts = new Dictionary<char, int>();
    foreach (char c in text)
    {
        counts[c] = counts.GetValueOrDefault(c) + 1;
    }
    return counts;
}

Pourquoi GetValueOrDefault ne demande aucune branche

counts.GetValueOrDefault(c) retourne la valeur stockée pour c si elle existe, et 0 -- la valeur par défaut du type -- sinon, plutôt que de lever une exception comme le fait le simple accesseur de l'indexeur. 0 est exactement la bonne réponse à « combien de fois c a-t-il été vu jusqu'ici » lors de sa première apparition, ce qui rend counts[c] = counts.GetValueOrDefault(c) + 1; correct qu'il s'agisse de la première apparition du caractère ou de sa centième : la même ligne gère les deux cas, parce que le point de départ pour « ajouter un » est déjà le bon dans les deux cas.

La version que ceci remplace, counts[c]++, n'est pas fausse dans l'esprit -- c'est exactement l'opération effectuée ici -- elle est fausse parce que la moitié lecture de cette affectation composée passe par le simple accesseur de l'indexeur, qui lève une KeyNotFoundException sur une clé qui n'a jamais été écrite, plutôt que par le plus indulgent GetValueOrDefault.

Pourquoi tout l'alphabet n'a pas besoin d'être pré-rempli

Une autre correction possible -- initialiser à 0 chaque caractère susceptible d'apparaître avant que la boucle ne s'exécute, pour que le simple indexeur ne rencontre jamais de clé manquante -- fonctionne, mais demande de connaître tout l'alphabet à l'avance et de pré-remplir une entrée pour chacun de ses caractères, dont la plupart ne seront jamais réellement utilisés par l'entrée. GetValueOrDefault évite d'avoir besoin de cet alphabet : les entrées sont créées paresseusement, exactement pour les caractères qui apparaissent réellement, ce qui explique aussi pourquoi un text vide produit correctement un dictionnaire vide plutôt qu'un dictionnaire rempli de zéros.

Coût

O(n) dans la longueur de `text` -- une recherche et une écriture dans le dictionnaire par caractère, toutes deux en O(1) en moyenne.
