Parenthèses équilibrées, trois types

Solution détaillée

Cette page contient la réponse complète et explique pourquoi chaque partie s'y trouve.

Le code

public static bool IsBalanced(string text)
{
    var closesFor = new Dictionary<char, char> { [')'] = '(', [']'] = '[', ['}'] = '{' };
    var stack = new Stack<char>();

    foreach (char c in text)
    {
        if (c == '(' || c == '[' || c == '{')
        {
            stack.Push(c);
        }
        else if (closesFor.ContainsKey(c))
        {
            if (stack.Count == 0 || stack.Pop() != closesFor[c])
            {
                return false;
            }
        }
    }
    return stack.Count == 0;
}

Pourquoi la vérification de pile vide vient en premier, dans la même expression

stack.Count == 0 || stack.Pop() != closesFor[c] repose sur l'évaluation court-circuitée de || : quand la pile est vide, le côté gauche vaut true et Pop() n'est jamais appelé du tout, si bien que l'InvalidOperationException qu'il lèverait autrement n'en a jamais l'occasion. Écrire les deux vérifications comme des instructions séparées fonctionne aussi, tant que la vérification de vacuité a bien lieu en premier et retourne bien avant d'atteindre l'appel à Pop() -- le risque en les séparant est qu'un refactoring ultérieur déplace l'une après l'autre sans que l'ordre soit aussi visiblement critique que lorsqu'elles partagent une seule expression court-circuitée.

Pourquoi la vérification finale porte sur la pile, pas sur ce qui a été vu pendant la lecture

"(()" ne rencontre jamais de parenthèse fermante en désaccord avec ce qui est ouvert -- il n'y a tout simplement pas assez de parenthèses fermantes pour atteindre le point de désaccord. Rien dans la lecture de gauche à droite ne le remarque jamais ; le seul endroit où cela se manifeste est que la pile contient encore un '(' non fermé une fois text épuisé. C'est exactement ce que vérifie return stack.Count == 0; : pas « ai-je jamais vu un désaccord », mais « reste-t-il quelque chose en attente d'être fermé ».

Coût

O(n) dans la longueur de `text` -- chaque caractère est examiné une fois, et chaque parenthèse fait au plus un empilement ou un dépilement.
