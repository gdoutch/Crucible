Recherche binaire avec une convention de point d'insertion

Solution détaillée

Cette page contient la réponse complète et explique pourquoi chaque partie s'y trouve.

Le code

public static int BinarySearchInsertionPoint(int[] sortedValues, int target)
{
    int low = 0;
    int high = sortedValues.Length - 1;

    while (low <= high)
    {
        int mid = low + (high - low) / 2;
        if (sortedValues[mid] == target)
        {
            return mid;
        }
        if (sortedValues[mid] < target)
        {
            low = mid + 1;
        }
        else
        {
            high = mid - 1;
        }
    }
    return ~low;
}

Pourquoi low est exactement le point d'insertion quand la boucle se termine

Deux invariants sont maintenus tout au long de la boucle, entretenus par la borne qui bouge à chaque comparaison : tout indice strictement inférieur à low contient une valeur connue pour être inférieure à target, et tout indice strictement supérieur à high contient une valeur connue pour être supérieure. La boucle continue de réduire cet écart jusqu'à ce que low et high se croisent -- low == high + 1 -- moment où low est le premier indice à partir duquel commence la région « connue supérieure », ce qui est précisément là où target devrait aller pour garder tout ce qui le précède plus petit et tout ce qui le suit non plus petit. Cela reste vrai que low atterrisse au milieu du tableau, à 0 (la cible appartient avant tout) ou à sortedValues.Length (la cible appartient après tout) -- le même invariant produit la bonne réponse aux deux extrémités sans vérification séparée pour l'une ou l'autre.

Pourquoi le complément, et pourquoi il est réversible

~x pour un x non négatif est défini comme -x - 1 -- pas -x. Ce -1 supplémentaire est ce qui fait que chaque indice non négatif correspond à un nombre négatif *distinct*, y compris 0 : ~0 == -1, sans ambiguïté différent d'un véritable résultat « trouvé à l'indice 0 » de 0, alors que -0 == 0 entrerait directement en collision avec lui. Ce même décalage est aussi ce qui rend l'encodage réversible dans l'autre sens : un appelant tenant un résultat négatif peut récupérer l'indice d'insertion avec un second complément, ~result, parce que ~(~x) == x pour tout entier x -- complémenter deux fois s'annule exactement. C'est la même convention que Array.BinarySearch et List<T>.BinarySearch utilisent, ce qui est précisément la raison pour laquelle il vaut la peine de la respecter plutôt que d'inventer un autre signal de « non trouvé ».

Coût

O(log n) dans la longueur de `sortedValues` -- chaque comparaison élimine la moitié de ce qu'il reste à chercher.
