Division With Two Distinct Failure Modes

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

Check both special cases before dividing at all

if (b == 0) {
    return (DivideStatus.DivideByZero, 0);
}
if (a == int.MinValue && b == -1) {
    return (DivideStatus.Overflow, 0);
}
return (DivideStatus.Ok, a / b);

Why the second check cannot be a catch block

It is tempting to let a / b run inside a try and catch whatever it throws -- but by the time it has thrown, the exception has already happened, at a cost, for an input this function is specifically supposed to recognise and handle *without* throwing at all. Worse, catching a bare OverflowException around the division and reporting it as DivideByZero (reusing the wrong-looking-but-nearby case) reports a reason for the failure that has nothing to do with what actually happened. Check a == int.MinValue && b == -1 explicitly, before the division ever runs.

If you are not certain integer division overflow-checks unconditionally in C# (unlike +/-/*, which only do inside a checked block), that is exactly the fact this exercise is built to make you confirm for yourself.
