Un coup de pouce dans la bonne direction. La réponse complète se trouve sur la page de la solution détaillée, donc rien ci-dessous ne la révèle.

La forme de la boucle

var deque = new LinkedList<int>();  // indices, valeurs décroissantes de l'avant vers l'arrière
for (int i = 0; i < values.Length; i++) {
    // 1. évincer de l'avant : les indices sortis de la fenêtre
    // 2. évincer de l'arrière : les indices dont la valeur <= values[i]
    // 3. ajouter i à l'arrière
    // 4. si la fenêtre est pleine, la valeur de l'avant est le max de cette fenêtre
}

Pourquoi l'éviction arrière utilise <=

Imaginez deux valeurs égales, l'une déjà dans la deque et values[i] qui arrive maintenant avec la même valeur. L'ancienne est sur le point de devenir inutile dès qu'elle sort de la fenêtre -- et quand cela arrive, la nouvelle, égale, est encore là et est tout aussi valable comme réponse. Garder l'ancienne quand même (en utilisant < au lieu de <= pour la vérification d'éviction) ne produit pas un maximum incorrect -- les ex æquo ne changent pas quelle est la plus grande valeur -- mais cela laisse des indices obsolètes et devenus inutiles s'accumuler dans la deque sans jamais être relus, ce qui fait toute la différence entre une deque qui reste petite et une deque qui regrossit lentement vers la taille de la fenêtre qu'elle était censée éviter de reparcourir.

L'éviction avant se produit avant l'éviction arrière, à chaque itération

Vérifier si l'indice de tête est sorti de la fenêtre doit se faire en premier, avant même de considérer quoi que ce soit sur la valeur courante -- sinon un indice de tête qui devrait déjà être parti pourrait encore être lu comme « le maximum courant » pour une itération de trop.
