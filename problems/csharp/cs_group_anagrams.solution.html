Group Anagrams

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

public static List<List<string>> GroupAnagrams(List<string> words)
{
    string Key(string word) => new string(word.OrderBy(c => c).ToArray());

    var groups = new Dictionary<string, List<string>>();
    foreach (var word in words)
    {
        var key = Key(word);
        if (!groups.TryGetValue(key, out var list))
        {
            list = new List<string>();
            groups[key] = list;
        }
        list.Add(word);
    }

    var result = new List<List<string>>();
    var emitted = new HashSet<string>();
    foreach (var word in words)
    {
        var key = Key(word);
        if (emitted.Add(key))
        {
            result.Add(groups[key]);
        }
    }
    return result;
}

Why grouping and ordering are two separate passes

The first loop's only job is correctness -- every word ends up in the list its anagram signature maps to, and TryGetValue plus a lazily-created list handles "is this the first word with this signature" without a separate ContainsKey check. It says nothing about what order groups itself would enumerate in, and nothing in Dictionary<TKey, TValue>'s contract promises that order matches insertion order -- it is an implementation detail of the current runtime, not part of the type's specification. The second loop is what actually produces the order the problem asks for: walking words again, in its own original order, and using HashSet<string>.Add's return value (true the first time a key is added, false after) to emit each group exactly once, at the point its first word appears.

Why the key is built once, as a local function

Key(word) is called twice per word across the two passes -- once while grouping, once while deciding emission order -- and defining it once as a local function keeps both call sites unable to quietly compute the signature two different ways. word.OrderBy(c => c) sorts the characters (an ordinal sort, since char compares by code point), and new string(...) turns the sorted IEnumerable<char> back into a string cheaply enough not to matter for words of realistic length.

Cost

O(n · k log k) where n is the number of words and k the length of the longest one -- sorting each word's characters dominates, run twice per word across the two passes. The grouping and ordering themselves are O(n) beyond that, using a dictionary and a hash set for O(1) average lookups.
