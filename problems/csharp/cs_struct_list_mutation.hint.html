Mutating Structs Inside a List

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

Read, mutate the local, write back

for (int i = 0; i < counters.Count; i++) {
    var c = counters[i];   // a copy
    c.Increment();         // mutates the copy
    counters[i] = c;       // writes the copy back into the list
}

What looks right and silently is not

counters[i].Increment(); builds, runs, and throws nothing -- and changes nothing. counters[i] is a property-style indexer access that hands back a *copy* of the struct stored at that position; Increment() then mutates that copy, which nothing holds a reference to and which is discarded the instant the statement finishes. The list's actual storage at index i is never touched. The same is true of foreach (var c in counters) c.Increment();, for the same underlying reason -- c is a copy, every time.

There is no way to get a genuine, list-backed reference to a struct element and mutate it in place through an ordinary indexer or foreach loop -- the read-modify-write pattern above, explicit about all three steps, is the standard fix.
