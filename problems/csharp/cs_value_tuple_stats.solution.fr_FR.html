Min, max et somme sous forme de tuple de valeurs

Solution détaillée

Cette page contient la réponse complète et explique pourquoi chaque partie s'y trouve.

Le code

public static (int Min, int Max, long Sum) Stats(int[] values)
{
    int min = values[0];
    int max = values[0];
    long sum = 0;

    foreach (int v in values)
    {
        if (v < min) { min = v; }
        if (v > max) { max = v; }
        sum += v;
    }

    return (min, max, sum);
}

Pourquoi sum est long dès sa toute première affectation

sum += v s'exécute une fois par élément, et chacune de ces additions se fait dans le type sous lequel sum a été déclaré. Si ce type est int, chaque addition est une addition int -- non vérifiée par défaut en C#, donc elle déborde silencieusement au lieu de lever une exception -- et le débordement s'est déjà produit au moment où une conversion ultérieure en long tenterait de le corriger. Déclarer long sum = 0; d'emblée signifie que chacune de ces additions est une addition long dès le départ, avec environ neuf trillions de marge plutôt qu'environ deux milliards.

Pourquoi min et max partent de values[0]

Initialiser les deux à partir du premier élément du tableau lui-même, plutôt qu'à partir de int.MinValue/int.MaxValue, signifie que les comparaisons à l'intérieur de la boucle n'ont jamais qu'à se demander « cet élément est-il plus extrême que tout ce qui a été vu jusqu'ici » -- vrai pour chaque élément d'un tableau entièrement négatif ou entièrement positif précisément parce que le point de départ est lui-même un élément réel, pas une sentinelle qui se trouve déjà être plus extrême que tout ce que le tableau pourrait réellement contenir. Les cas de test fixes pour un tableau entièrement négatif et un tableau entièrement positif existent parce qu'initialiser min à partir de int.MaxValue (ou l'inverse pour max) fonctionne par chance sur un tableau qui chevauche zéro, et ne se révèle faux que sur un tableau qui ne le fait pas.

Le tuple lui-même

return (min, max, sum); construit le tuple de façon positionnelle -- les noms Min, Max et Sum issus du type de retour sont attachés par le compilateur selon la position, pas en faisant correspondre un nom écrit au site d'appel. Un appelant peut alors écrire var result = Stats(values); result.Min et obtenir un champ véritablement nommé, pas un indice dans un tableau anonyme.

Coût

O(n) dans la longueur de `values` -- un seul passage, trois valeurs courantes mises à jour par élément, aucune allocation.
