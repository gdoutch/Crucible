Regrouper les anagrammes

Solution détaillée

Cette page contient la réponse complète et explique pourquoi chaque partie s'y trouve.

Le code

public static List<List<string>> GroupAnagrams(List<string> words)
{
    string Key(string word) => new string(word.OrderBy(c => c).ToArray());

    var groups = new Dictionary<string, List<string>>();
    foreach (var word in words)
    {
        var key = Key(word);
        if (!groups.TryGetValue(key, out var list))
        {
            list = new List<string>();
            groups[key] = list;
        }
        list.Add(word);
    }

    var result = new List<List<string>>();
    var emitted = new HashSet<string>();
    foreach (var word in words)
    {
        var key = Key(word);
        if (emitted.Add(key))
        {
            result.Add(groups[key]);
        }
    }
    return result;
}

Pourquoi regroupement et ordre sont deux passages séparés

La première boucle a pour seul rôle la correction -- chaque mot finit dans la liste que désigne sa signature d'anagramme, et TryGetValue associé à une liste créée paresseusement gère « est-ce le premier mot avec cette signature » sans vérification ContainsKey séparée. Elle ne dit rien de l'ordre dans lequel groups lui-même énumérerait, et rien dans le contrat de Dictionary<TKey, TValue> ne promet que cet ordre corresponde à l'ordre d'insertion -- c'est un détail d'implémentation de l'environnement d'exécution actuel, pas une partie de la spécification du type. La seconde boucle est ce qui produit réellement l'ordre demandé par le problème : en reparcourant words, dans son propre ordre d'origine, et en utilisant la valeur de retour de HashSet<string>.Add (vrai la première fois qu'une clé est ajoutée, faux ensuite) pour émettre chaque groupe exactement une fois, au moment où son premier mot apparaît.

Pourquoi la clé est construite une seule fois, comme fonction locale

Key(word) est appelée deux fois par mot au total sur les deux passages -- une fois pendant le regroupement, une fois en décidant de l'ordre d'émission -- et la définir une seule fois comme fonction locale empêche les deux sites d'appel de calculer discrètement la signature de deux façons différentes. word.OrderBy(c => c) trie les caractères (un tri ordinal, puisque char se compare par point de code), et new string(...) reconvertit l'IEnumerable<char> trié en chaîne, assez peu coûteux pour ne pas compter sur des mots de longueur réaliste.

Coût

O(n · k log k) où n est le nombre de mots et k la longueur du plus long -- trier les caractères de chaque mot domine, exécuté deux fois par mot au total sur les deux passages. Le regroupement et l'ordonnancement eux-mêmes sont O(n) au-delà de cela, grâce à un dictionnaire et un ensemble de hachage pour des recherches en O(1) en moyenne.
