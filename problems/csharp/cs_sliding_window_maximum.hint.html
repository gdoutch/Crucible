The shape of the loop

var deque = new LinkedList<int>();  // indices, values decreasing front-to-back
for (int i = 0; i < values.Length; i++) {
    // 1. evict from the front: indices that fell out of the window
    // 2. evict from the back: indices whose value <= values[i]
    // 3. add i to the back
    // 4. if the window is full, front's value is this window's max
}

Why the back eviction uses <=

Picture two equal values, an earlier one already in the deque and values[i] arriving now with the same value. The earlier one is about to become useless the moment it ages out of the window -- and when it does, the later, equal one is still there and is just as valid an answer. Keeping the earlier one around anyway (using < instead of <= for the eviction check) does not produce a wrong maximum -- ties do not change what the biggest value is -- but it does let stale, no-longer-useful indices pile up in the deque without ever being read again, which is the difference between the deque staying small and it slowly growing back toward the size of the window it was supposed to avoid rescanning.

Front eviction happens before back eviction, every iteration

Checking whether the front index has aged out of the window has to happen first, before anything about the current value is considered -- otherwise a front index that should already be gone could still be read as "the current maximum" for one iteration too long.
