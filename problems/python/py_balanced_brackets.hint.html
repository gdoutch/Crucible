Balanced Brackets

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

True if every (, [ and { is closed by its own kind of bracket, in the right order. Any other character is ignored entirely.

Why counting does not work

The instinct is to count openers and closers and check they match. Try that against the fixed cases:

InputCounts balance?Actually balanced?
()yesyes
)(yesno — closed before opened
([)]yesno — wrong order
(]yes, if you count all brackets togetherno

Counting throws away the two things that matter: which bracket was opened, and when.

The structure is a stack

Brackets nest. The one you must close next is always the one you opened most recently — last in, first out. That is the definition of a stack, and in Python a plain list is one: append to push, pop to take the last item off.

So the algorithm is one pass with three kinds of character:

  1. An opener — push it and move on.
  2. A closer — the top of the stack must be its matching opener. Pop it and compare. If the stack is empty, there is nothing to close and the answer is False immediately.
  3. Anything else — ignore it.

And then the ending

Running out of characters is not the same as succeeding. If anything is still on the stack, those brackets were opened and never closed — so the final answer is "the stack is empty", not True.

Two of the four failure modes are detected during the loop (a closer with nothing open, a closer that does not match), and the third is detected only after it: ((( never fails a comparison, because there are no comparisons to fail.

Matching closers to openers

You need to know that ) goes with (. A dict is the natural home for that, and mapping closer → opener is more useful than the other way round, because it doubles as your "is this a closer?" test.

Python's in works on strings as well as dicts, so if char in "([{" is a neat way to ask "is this an opener?". Watch out for one thing: "" in "([{" is True, since every string contains the empty string. Not a problem when iterating over characters, but it surprises people.

closing = {")": "(", "]": "[", "}": "{"}
stack = []

Both failure checks can be written as a single condition joined with or, provided you put the emptiness test first — Python's or short-circuits, so the pop is only reached when there is something to pop.

Check yourself before you press Go

  • "" → True. Nothing unbalanced about nothing.
  • ) → False, and no exception from popping an empty list.
  • (] → False — right shape, wrong type.
  • ([)] → False — interleaved is not nested.
  • ( → False — left open.
  • a(b[c]d)e → True — other characters ignored.
