Two Sum

Worked solution

This page contains the complete answer and explains why each part of it is there.

The idea

Trade memory for time. Instead of searching for a partner, compute what the partner must be — target - value — and ask a dictionary whether you have already passed it. One pass, one dict, constant-time lookups.

The code

def two_sum(numbers, target):
    """Return (i, j) with i < j and numbers[i] + numbers[j] == target."""
    seen = {}
    for index, value in enumerate(numbers):
        complement = target - value
        if complement in seen:
            return (seen[complement], index)
        seen.setdefault(value, index)
    return None

Five lines, and three of them encode a rule from the specification.

Look up before you insert

The order of the last two statements in the loop is the whole reason the "same element twice" rule is respected.

At the moment of the lookup, seen contains only elements at indices strictly less than index. So any hit is a genuinely different element, and its index is necessarily smaller — which delivers i < j without a single comparison.

Insert first and [4] with target = 8 returns (0, 0): the element pairs with itself. The single number fixed case ([5], target 5) is a milder version of the same trap.

setdefault, not plain assignment

seen.setdefault(value, index) stores index only if value is not already a key. So for repeated values the dict remembers the earliest position.

Why that is the right choice: the stored index becomes the i of any pair found later. Since every later element sees the same dict, keeping the earliest index yields the smallest possible i — and it can never lose a solution, because if a later duplicate could pair with something, the earlier one could too.

With seen[value] = index instead, [3, 3, 4] with target 7 would return (1, 2) where (0, 2) is the better answer. No shipped test distinguishes them, but the randomised cases can — and the specification asks for the tightest pair.

Two equal values at different positions are a valid pair, and the lookup-before-insert discipline is what lets index 1 find index 0 without index 0 having found itself.

[] and [5] → None

The empty list never enters the loop. The single element looks up its complement in an empty dict, misses, records itself, and falls out of the loop. Both reach the final return None.

That trailing return None is explicit on purpose. Python would return None anyway by falling off the end of the function, but writing it says the absence of a pair is a designed outcome rather than an oversight.

"Smallest second index" comes free

The function returns the moment it finds a match. The index it returns on is therefore the first position in the whole list that has a partner behind it — which is exactly the smallest possible j. No candidate list, no min, no sorting.

The nested-loop version does not get this for free. Iterating i in the outer loop and j in the inner one finds pairs in order of smallest i, not smallest j, and returns a different (still valid) pair when several exist.

ApproachTimeSpace

Dict of seen valuesO(n) average O(n)

"Average" is the honest qualifier: dict lookups are O(1) amortised, with a pathological worst case if every key collides. For integers, Python's hash is the value itself and this does not arise in practice.

Wrong turns worth recognising

Returning values instead of indices. (3, 3) rather than (0, 1). The harness prints what you return, so this fails visibly — but it is worth noticing that the values are the easy half and the indices are what makes the problem worth asking.

if complement in numbers. Using the list membership test instead of the dict looks like the same thing and is O(n) per element — quietly restoring the quadratic behaviour the dict was there to avoid. It also finds the element itself, and then numbers.index() returns the first match rather than the one you meant.

Building the whole dict first, then scanning. Two passes, and the self-pairing problem comes back: every element's complement lookup can now find the element itself, so you need an explicit seen[complement] != index guard. The single-pass version deletes that whole category of bug.
