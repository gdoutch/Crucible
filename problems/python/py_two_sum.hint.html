Two Sum

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

A tuple (i, j) with i < j and numbers[i] + numbers[j] == target, or None. Indices, not values.

The nested-loop version

Try every pair: for each i, try every j after it. It is five lines, it is obviously correct, and it is O(n²). Write it first if it helps you get the index conventions straight — then throw it away, because the interesting version is a single pass.

Turn the search inside out

Standing at index j holding numbers[j], you do not need to search for "some pair that works". You know exactly which number would complete it:

complement = target - numbers[j]

So the only question left is: have I already seen that number, and if so, where? That is a lookup, not a search — and a dict answers it in constant time.

Build the dict as you go: value → the index it was found at. At each element, look up the complement before recording the current value, and you are done.

Why looking up before inserting matters

Consider numbers = [4] and target = 8. The complement of 4 is 4. If you insert first and then look up, you find yourself and return (0, 0) — using one element twice, which the problem forbids.

Check first, insert second, and the element can only ever pair with something strictly earlier. That also gives you i < j for free, with no comparison or sorting.

Duplicates: two different questions

The fixed case [3, 3] with target 6 must return (0, 1). Two equal values at different positions are a perfectly good pair — it is the same index twice that is banned. Check that your code distinguishes those.

What should the dict do when the same value appears twice? Keep the first index. It is the only one that can be the smaller half of a pair with anything later, and keeping it makes the tie-break rule below come out right. Plain seen[value] = index overwrites; there is a dict method that only sets a key if it is missing.

Which pair, when several work?

"The one whose second index is smallest." Read that carefully and it turns out to require no extra code at all: if you return as soon as you find a match, the j you return on is by definition the earliest j that had a partner. Just do not collect candidates and choose at the end.

Still stuck? A bigger nudge 
seen = {}                      # value -> first index it appeared at
for index, value in enumerate(numbers):
    complement = target - value
    if complement in seen:
        return (seen[complement], index)
    # record this value, without clobbering an earlier equal one
return None

One line to fill in. enumerate gives you index and value together, which is nearly always better than range(len(numbers)) in Python.

Check yourself before you press Go

  • Empty list → None.
  • One element → None, even if it is exactly half the target.
  • [3, 3], target 6 → (0, 1).
  • No pair at all → None, not an exception.
  • Are you returning a tuple of two ints, smaller index first?
