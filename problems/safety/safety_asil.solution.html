ASIL Determination

Worked solution

This page contains the complete answer and explains why each part of it is there.

The idea

Two correct answers, and choosing between them is the actual content of the exercise. One transcribes the standard's table; the other computes it from the rule the table happens to obey. They agree on all thirty-six cells.

The table version — what the reference ships

/* ISO 26262-3 Table 4, written out cell by cell. */
static const char *const ASIL[3][4][3] = {
    /*        C1    C2    C3   */
    {   /* S1 */
        { "QM", "QM", "QM" },   /* E1 */
        { "QM", "QM", "QM" },   /* E2 */
        { "QM", "QM", "A"  },   /* E3 */
        { "QM", "A",  "B"  },   /* E4 */
    },
    {   /* S2 */
        { "QM", "QM", "QM" },
        { "QM", "QM", "A"  },
        { "QM", "A",  "B"  },
        { "A",  "B",  "C"  },
    },
    {   /* S3 */
        { "QM", "QM", "A"  },
        { "QM", "A",  "B"  },
        { "A",  "B",  "C"  },
        { "B",  "C",  "D"  },
    },
};

const char *asil_for(int severity, int exposure, int controllability)
{
    return ASIL[severity - 1][exposure - 1][controllability - 1];
}

The - 1s convert the standard's 1-based classes to C's 0-based indices. Doing that conversion in one place, at the point of use, is what keeps the table itself readable as the table.

const char *const — a constant pointer to constant characters. The inner const stops the strings being modified, the outer one stops the array's entries being reassigned, and together they let the whole thing live in read-only memory.

The computed version

Every axis contributes equally and additively, so the rung of the ladder is a linear function of the sum:

const char *asil_for(int severity, int exposure, int controllability)
{
    static const char *const LADDER[] = { "QM", "A", "B", "C", "D" };

    int rung = severity + exposure + controllability - 6;
    if (rung < 0) {
        rung = 0;
    }
    return LADDER[rung];
}

Where the 6 comes from: the anchor S3 E4 C3 sums to 10 and must land on rung 4 (D), so the offset is 10 - 4 = 6. Check the other end: S1 E1 C1 sums to 3, giving -3, clamped to 0 — QM. And every step down any axis reduces the sum by one, which reduces the rung by one, which is precisely the stated rule.

The clamp is not optional. Ten of the thirty-six cells produce a negative rung — as low as -3 — and LADDER[-3] reads memory before the array. This is the single most likely bug in the computed version, and — because what it reads is usually some other string constant — it can print something that looks almost plausible.

So which should you write?

The computed version is nine lines against forty and cannot contain a mistyped cell. In most code that settles it.

In safety code it does not, and the reason is worth internalising:

The table can be checked against the standard by inspection, one cell at a time. The formula can only be checked by an argument — and an argument that the formula reproduces the table is a proof someone has to construct, review and re-review whenever anything changes.

An assessor's question is not "is this correct?" but "how do you know, and can you show me?". Thirty-six cells against thirty-six cells is a review that terminates. Confirming that a linear formula reproduces a table from a standard is a review that requires the reviewer to be as clever as the author, and to stay that clever under time pressure.

There is also a durability argument. The linearity is an observed property of this edition's table, not a rule the standard states. If a future edition perturbs one cell, the table version needs one edit and the formula version needs rewriting — and, worse, the formula version's failure would be silent, because nothing in it names the cell that changed.

This is a general pattern, not a quirk of ISO 26262. Wherever the specification is an enumeration, prefer code shaped like an enumeration. Cleverness that compresses a specification is buying brevity with auditability, and in this domain that is the wrong way round.

The table, and how the rule generates it

Every cell, with the rung in parentheses:

S1S2S3
C1C2C3C1C2C3C1C2C3
E1QMQMQMQMQMQMQMQMA
E2QMQMQMQMQMAQMAB
E3QMQMAQMABABC
E4QMABABCBCD

Exactly half the cells — eighteen of thirty-six — are QM. That is the shape of the domain, not an accident: most hazards in most situations do not need a safety requirement, and the ones that do are concentrated in the corner where severe, frequent and uncontrollable meet.

Returning the string

Both versions return a pointer to a string literal, which has static storage duration — it exists for the whole run, so the harness can read it after the function returns. The failure mode to avoid:

char buffer[4];                  /* automatic storage */
snprintf(buffer, sizeof buffer, "%s", "B");
return buffer;                   /* dangling as soon as we return */

The lifetime ends at the closing brace. The pointer usually still looks valid for a moment, which is why this bug survives testing and fails in production.

Note also what the function does not do: it returns "QM", not "ASIL QM". QM is not an ASIL, and the harness renders it accordingly — a presentation decision that belongs in the presentation layer.

Cost

O(1) either way: three subtractions and an array index, or an addition, a comparison and an index. The table costs about 300 bytes of read-only data. Neither is measurable, which is exactly why the choice can be made on reviewability alone.

Wrong turns worth recognising

Forgetting the - 1s. ASIL[severity][exposure][controllability] with 1-based inputs reads one plane, one row and one column too far — off the end of the array for S3. It compiles, and it produces garbage that occasionally looks like an answer.

Validating inputs that cannot be invalid. The problem guarantees the ranges, so a defensive branch here is unreachable code. In certified work unreachable code is a finding in itself — you are asked to show every line is exercised. Where the guarantee is real, rely on it and say so in a comment.

Treating the axes as unequal. Severity feels more important than exposure, so it is tempting to weight it. The rule says one step is one step, whichever axis it is on, and the three cells in the one step down each axis in turn test are all ASIL C precisely to pin that down.
