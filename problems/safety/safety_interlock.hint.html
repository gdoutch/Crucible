Level Crossing Interlock

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

A pure function. Given what the sensors say right now — trains approaching, trains in the crossing, where the barrier is — decide two outputs: the road signal, and where the barrier should be heading.

You have no memory between calls and you do not need any. Everything you need is in the three arguments.

Read the two safety properties as your specification

They are not a checklist to satisfy afterwards. They are the problem, and each one tells you about one output.

PropertyWhat it constrains
S1 a train is in the crossing only while the barrier is fully down when you must command the barrier down — and how early
S2 the signal is green only while the barrier is fully up when you may show green

S1 is the easy half

The barrier takes two ticks to fall, so it must start falling the moment anything is detected — not when a train reaches the crossing, by which point it is far too late. So: any train anywhere, approaching or already in the crossing, means target BARRIER_DOWN.

Note what that single condition also handles for free: a train appearing while the barrier is halfway back up. There is nothing special about reversing — it is the same decision as lowering was in the first place.

S2 is the half people get wrong

Here is the tempting one-liner:

*signal_out = (approaching > 0 || in_crossing > 0) ? SIGNAL_RED : SIGNAL_GREEN;

Read S2 again and find the hole. The last train leaves; there is now no train anywhere; this line turns the signal green — and the barrier is still fully down, because it has not had a single tick to move yet.

The lesson is worth more than the problem: the signal must follow where the barrier actually is, not where you have told it to go. Commanding a change and observing one are different things, and the gap between them is exactly where interlocks fail.

So the green condition is not "no trains". It is "no trains and the barrier has arrived". One of your three arguments answers the second half.

The two outputs are not symmetrical

When the crossing is clear you can start raising the barrier immediately, but you cannot show green until it gets there. So there is a window of two ticks where your answer is "target BARRIER_UP, signal SIGNAL_RED" — the trace prints RED UP, which looks contradictory the first time you see it and is the correct behaviour.

Going the other way there is no such window: the moment a train is detected both outputs change together.

Details

  • approaching and in_crossing are counts. Two trains can be in the approach section at once, and one of them entering the crossing does not clear the other. Test > 0, not == 1.
  • Write BARRIER_UP or BARRIER_DOWN through target_out — never BARRIER_MOVING. That is a place the barrier can be, not a place you can send it, and the harness rejects it.
  • Write to both out-parameters on every path. The harness clears them before each call, so a path that forgets one is reported as INVALID rather than quietly reusing the last value.
  • Some scenarios are unsurvivable — the barrier cannot teleport case gives you no ticks between seeing the train and it arriving. Its expected output is UNSAFE, and matching that is the correct behaviour, not a failure.
Still stuck? A bigger nudge 
void crossing_command(int approaching, int in_crossing, int barrier,
                      int *signal_out, int *target_out)
{
    if (/* any train anywhere */) {
        *signal_out = SIGNAL_RED;
        *target_out = BARRIER_DOWN;
        return;
    }

    *target_out = BARRIER_UP;
    *signal_out = /* green only if the barrier has actually got there */;
}

Six lines. If yours is much longer, you are probably enumerating the twelve combinations of the three inputs rather than expressing the two rules.

Check yourself before you press Go

  • The very first line of every run is GREEN UP — nothing is coming and the barrier starts up.
  • After the last exit there are two RED UP lines before any GREEN UP.
  • A second approach during the raise flips straight back to RED DOWN.
  • With two trains approaching, one entering does not release the barrier.
  • Every run that had enough warning ends SAFE.
