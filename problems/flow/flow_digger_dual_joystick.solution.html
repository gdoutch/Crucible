Everything else is as in Digger Drive Control. The seat joystick is still operator-relative. The console joystick is already in the machine's frame, so it is never inverted.

The key insight: the two joysticks live in different frames. The seat stick needs the seat position to become a machine direction. The console stick is machine-forward by construction. Both are reduced to one common form, a machine-frame direction, before they are compared.

Arbitration rule

The controller first decides the seat state, then which source is allowed, then reduces it to one command.

Safety rules to specify

ConditionCommand
Seat moving, unknown, or the two switches disagree Neutral
Seat unoccupiedNeutral
After any seat rotation Neutral until both joysticks are in neutral, then re-engage
Source changes (master lost or regained) Neutral until the newly active stick is in neutral
Direction reversal Only below a speed threshold, and via neutral
Lost, stale or corrupt message from the active source Neutral, and raise a fault

The easy miss is the console joystick held forward through a rotation. Seat north: console forward means machine forward. Rotate to south: the console is now disabled, and the seat stick takes over with its direction inverted. If the seat stick happens to be held, the machine can change direction on its own, with nobody having chosen it.

The re-engage rule must therefore cover both joysticks, and must apply on every change of source, not only after a rotation.

The second miss is treating "disabled" as "absent". A disabled console joystick is still sending messages. Its deflection must be ignored, but its message must not be allowed to fault the machine, and it must not be lost from the re-engage check, because it becomes the master again when the seat returns north.

Why this split

All sources are raw. One controller owns the selection. The selection rule is then one function of (seat state, console, seat stick), which can be analysed, unit tested as a truth table, and traced to the hazard analysis.

A common alternative is to put the "disable" in the console joystick's own electronics, so it goes quiet when the seat is south. That puts safety logic in a second place, and the seat position would have to be sent to it. It is better as a rule in the controller. A hardware interlock is the exception, and is the point below.

Points to raise

  • "Master" is not defined. Does it mean it wins every conflict, or only that it is preferred when both are active? With opposing deflections, neutral is the more conservative answer. Ask which one the risk assessment wants.
  • Unoccupied seat. With the seat north and nobody in it, should the console stick drive the machine? An operator standing at the console is a legitimate use on some machines, and is a hazard on others. This decides whether the occupancy sensor gates the console at all.
  • A failed console joystick. Falling back to the seat stick keeps the machine usable. It also means a failed master is quietly replaced. Neutral and a fault is the safer default.
  • Independent interlock. Does the risk assessment accept software alone for the disable, or does it need a hardware interlock on seat position? That drives the required safety integrity level, for example the Performance Level under ISO 13849, or the ISO 25119 level for this type of machine.

Self-marking checklist

  • Both joysticks drawn, each with its own link to the controller?
  • Console stick labelled as machine-frame, seat stick as operator-relative?
  • Console never inverted; seat stick inverted only when south?
  • Console disabled when south, and ignored whatever it reads?
  • Master rule stated for the north case, including both deflected?
  • Neutral after rotation covers both sticks?
  • Display shows which source is active?
  • Neutral on any doubt: moving, unknown, unoccupied, lost message?
