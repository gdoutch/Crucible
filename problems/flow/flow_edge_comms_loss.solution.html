Losing the Network, Then the Coordinator

Worked solution

A model answer to compare against. Yours may differ in names and split; check it covers the same data, checks and failure handling.

Detection and response

The key idea is the lease. Every instantaneous command is valid for a few seconds, and the coordinator refreshes it every second. The sandbox needs no knowledge of why commands stopped. It only needs a clock of its own.

Running without the network

  • The schedule is stored in the coordinator, so it keeps running.
  • Time: a real-time clock, last synchronised over the network. Track the time since the last sync, and the worst-case drift.
  • Schedules have a horizon, for example 24 hours. Past it, fall back to the device's default behaviour.
  • Telemetry: a bounded ring buffer in flash, with sequence numbers. When full, drop the oldest, or thin it out. Never block control because the buffer is full.

Recovery

  • A rebooted coordinator reads its persisted schedule. It does not replay commands that have already expired.
  • It re-establishes the lease, then ramps power up, rather than stepping.
  • Buffered telemetry is sent after live data, at a limited rate.
  • Randomised delay before resuming high power. Thousands of chargers stepping to 7 kW at once is a load step on the grid.

"Fail safe" does not mean "turn off". For a charger, zero is usually fine. For a heat pump in winter, or a battery providing backup power, off may be the unsafe choice. The safe state is defined per device type, by the device maker.

Point to raise

If the sandbox hangs, the coordinator can see it, but can it act? It needs a path that does not depend on the sandbox, such as a reset line or a hardware enable to the device.

Self-marking checklist

  • Each failure has a named detector?
  • Schedule survives loss of the network?
  • Time keeping without the network considered?
  • Lease, or equivalent, on commands to the sandbox?
  • Bounded telemetry buffer?
  • Ramp and randomised delay on recovery?
  • Safe state defined per device, not assumed to be off?
