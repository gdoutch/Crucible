The OEM sandbox is not trusted either. It is contained: separate silicon, a single defined link, and nothing it sends is believed without checking.

Inbound checks, in order

Cheap checks first, so junk is rejected before it costs anything.

  1. Framing: length field within a fixed maximum, frame complete, frame CRC good.
  2. Authenticity: signature or MAC verified with a key held only in the coordinator.
  3. Freshness: monotonic counter or nonce, and a time window. Rejects replays.
  4. Allow-list: message type is one the policy names. Unknown types are dropped, not passed through.
  5. Semantics: every field in range for this device and this site. 3 kW is fine; 300 kW is not.
  6. State: allowed now? For example, no discharge while a fault is active.
  7. Rate: no more than N commands per second.

Anything that fails is dropped, counted and logged. The firewall fails closed.

A compromised radio processor

CanCannot
Drop, delay or reorder messagesForge a command: it has no signing key
Replay old messagesMake a replay succeed: freshness check
Send malformed framesCrash the coordinator: bounded parser
Deny serviceReach the OEM sandbox: no link exists

TLS alone is not enough. It ends on the radio processor, which is in the untrusted zone. Commands need end-to-end authentication from the cloud to the coordinator.

Parsing untrusted bytes

  • Fixed maximum frame size. Static buffers. No malloc.
  • Length fields checked before use. No pointer arithmetic on unchecked values.
  • One parser, small, and fuzzed in CI.
  • Watchdog, so a hang becomes a reset rather than a stuck firewall.

Point to raise

The policy itself is a target. The allow-list and range limits must be signed, versioned and protected against rollback, like firmware.

Self-marking checklist

  • Radio processor placed in the untrusted zone?
  • OEM sandbox treated as contained, not trusted?
  • End-to-end authentication, not just TLS?
  • Replay protection?
  • Allow-list and range checks?
  • Outbound filtering as well as inbound?
  • Fail closed?
