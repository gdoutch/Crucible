Bus and messages

All links run over CAN, for example J1939 or CANopen.

Every safety-relevant message carries an alive counter and a CRC. Each receiver monitors a timeout.

Core logic in the drive controller

  1. Read the joystick as "forward relative to the operator".
  2. Seat faces north: pass the direction through. Seat faces south: invert it. Forward on the stick then always means the way the operator is looking.
  3. Map the gear request to an allowed gear, limited by machine speed.

The key insight is that the joystick is fixed to the seat. Its reading is relative to the operator, not to the machine. The seat position is what turns it into a machine-frame direction.

Safety rules to specify

ConditionCommand
Seat moving, position unknown, or the two switches disagree Neutral
Seat unoccupiedNeutral
After any seat rotation Neutral until the joystick returns to neutral, then re-engage
Direction reversal Only below a speed threshold, and via neutral
Lost, stale or corrupt message Neutral, and raise a fault

The "joystick must return to neutral after rotation" rule is the one most often missed. Without it, a stick held forward while the seat turns becomes a stick held in reverse, and the machine lurches the wrong way.

Why this split

The sensors report raw state only. All interpretation sits in one controller.

The safety logic is then in a single place. It can be analysed, unit tested and traced to the hazard analysis.

Point to raise

Is the inversion allowed in software alone? Or does the risk assessment demand an independent hardware interlock on seat position?

That decision drives the required safety integrity level, for example the Performance Level under ISO 13849, or the ISO 25119 level for this type of machine.

Self-marking checklist

  • Joystick, seat sensor and controller all drawn, with a link between each?
  • Joystick data labelled as relative to the operator?
  • Seat sensor data includes a moving or validity signal, not just north / south?
  • Controller output carries direction and gear?
  • Fail-safe behaviour stated (neutral on any doubt)?
  • Neutral-before-re-engage after rotation mentioned?
