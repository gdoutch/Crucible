Even Parity Bit

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

One bit that, appended to data, would make the total number of set bits even. That is the whole of what "even parity" means: it is not a property of data alone, it is a property chosen to hold once parity joins it.

The idea in one sentence

parity is '1' exactly when data itself has an odd number of ones -- because adding one more one is what turns an odd count even. Count the ones in data; the answer is whether that count is odd.

You already know an operator that answers this

XOR of two bits is '1' exactly when they differ -- an odd number of them are '1'. Chain that across all eight bits and the same fact holds: the running XOR is '1' exactly when an odd number of the bits seen so far were '1'. XOR the whole vector together and you have your answer, with no need to count anything or compare to a number.

Doing that without writing out eight terms

VHDL-2008 gives four of the bitwise operators -- and, or, xor and their negations -- a second, unary form: put one of them directly in front of an array and it folds the whole thing down to a single bit of the same type, left to right, as if you had chained the ordinary two-argument operator between every element.

parity <= ???;   -- one operator, one signal, no index, no loop

Nothing about the port list needs to change for this -- data is already exactly the array such an operator expects.

Check yourself before you press Go

  • 00000000 → 0. Zero is even; nothing to add.
  • 00000001 → 1. One bit is odd.
  • 11111111 → 0. Eight is even too -- the same answer as all-zero, from the opposite end. A solution that treats "all zero" as a special case rather than actually computing a count gets this one wrong.
