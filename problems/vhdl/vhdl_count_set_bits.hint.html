Count Set Bits

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

How many of the 8 bits of value are '1' — the population count, wired up as a circuit rather than written as a loop in a program. count needs to be right for every one of the 256 possible inputs at once: there is no "next instruction" here, only a description of the wire.

This is a lookup, not a loop

A process is allowed to loop internally — for i in value'range loop is completely ordinary VHDL — but what it describes is still combinational hardware, not a sequence of steps that happen over time. Whatever the process computes has to settle to count's final value the moment value changes, because the testbench only gives it one wait for 1 ns before it reads the answer back.

Two shapes both work here. One is a process with value in its sensitivity list, looping over the 8 bits and accumulating a count in a variable. The other has no process at all: eight terms added together with VHDL's + on unsigned, each term being a bit widened to a number that is either 0 or 1. Both describe the same hardware; the loop is just a shorter way to write it.

The trap: every bit needs a target, every path needs an assignment

An if with no else describes a latch. If a process only assigns count inside a condition that is not always true, simulation remembers whatever count held from the previous run — exactly the behaviour real synthesis would give you too, since "keep the old value" is what a latch is. Give every branch of every decision somewhere for count to end up, or compute it as one expression with nothing conditional in the way at all.

Getting a number back out of bits

count is a std_logic_vector, not an integer, so a running total kept as a plain VHDL integer variable needs converting before it can be assigned to it. ieee.numeric_std is where that conversion lives — the same package that gives ordinary arithmetic to std_logic_vector in the first place, by way of its unsigned and signed types.

Still stuck? A bigger nudge

The loop version, with the conversion left as the one blank to fill in:

process (value)
    variable total : integer range 0 to 8;
begin
    total := 0;
    for i in value'range loop
        if value(i) = '1' then
            total := total + 1;
        end if;
    end loop;
    count <= ???;  -- total, turned back into an 4-bit std_logic_vector
end process;

to_unsigned(total, count'length) is the function that does it — the target width, count'length, comes from count itself, so it is never hand-typed as a literal 4.

Check yourself before you press Go

  • 00000000 → 0000. All the branches that give up early still need to reach this on the emptiest input.
  • 11111111 → 1000. The only fixed case where the answer needs count's own top bit.
  • 10101010 → 0100: four bits, spread out rather than adjacent, so a run-length shortcut would get this one wrong.
