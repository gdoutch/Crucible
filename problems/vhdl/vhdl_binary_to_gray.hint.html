Binary to Gray Code

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

What you are being asked for

Four output bits, each a simple function of the input -- no state, no memory of a previous value, just this input mapped to this output. That makes it a fit for four independent concurrent signal assignments, one per bit of gray, rather than a process.

The idea in one sentence

The top bit copies straight across. Every bit below it is the XOR of two binary input bits: the one at its own position, and the one immediately above that.

gray bitformula
3 (top)bin(3)
2bin(3) xor bin(2)
1bin(2) xor bin(1)
0bin(1) xor bin(0)

Four lines, each one XOR. Nothing here needs a loop.

The trap: which direction is "one above"

bin(i+1) xor bin(i), not bin(i) xor bin(i-1). Both read as "XOR this bit with its neighbour", and both compile -- a std_logic_vector has no notion of which direction is "correct", so getting it backwards produces four well-formed bits for every input, all of them wrong except at zero, where both directions happen to agree.

One way to keep the direction straight: the top bit (bin(3)) never gets XORed with anything -- it has nothing above it. Every other bit's formula involves the bit one position higher than itself. If a formula for gray(0) ever mentions bin(3) or wraps around, the direction has gone the wrong way.

Check yourself before you press Go

  • 0000 → 0000. Binary and Gray agree at zero -- and, awkwardly, this is also the one case a backwards shift gets right by accident, so do not stop here.
  • 0001 → 0001.
  • 1010 → 1111. Every output bit differs from the corresponding input bit.
