Kth Largest With a Bounded Min-Heap

Keep only the k largest seen so far

PriorityQueue<Integer> heap = new PriorityQueue<>();
for (int v : values) {
    heap.offer(v);
    if (heap.size() > k) {
        heap.poll();
    }
}
return heap.peek();

The default ordering is already the one you want

`new PriorityQueue<Integer>()` orders by natural ordering, smallest first -- `poll()` removes the *smallest* element, not the largest. That sounds backwards for "find the largest", but it is exactly right for this approach: capping the heap at size `k` and evicting the smallest whenever it grows past that keeps precisely the `k` largest values encountered so far, and evicting the smallest of *those* is how a new, larger value gets to displace the weakest current member of that top-`k`. Reaching for `Collections.reverseOrder()` to build a max-heap instead solves a different problem than this approach needs solved.

Evict only once the heap's size actually exceeds `k` -- checking `> k` rather than `>= k` matters, because the second version starts evicting before the heap has even finished filling up to `k` elements.
