Word Frequency Without a Null Pointer Exception

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

One line, no branch

Map<String, Integer> counts = new TreeMap<>();
Scanner scanner = new Scanner(text);
while (scanner.hasNext()) {
    String word = scanner.next();
    counts.put(word, counts.getOrDefault(word, 0) + 1);
}
return counts;

What breaks if you reach for `get` instead

`counts.put(word, counts.get(word) + 1);` compiles cleanly and throws `NullPointerException` the very first time `word` is seen. `get` returns `null` for a missing key -- an entirely ordinary, documented return value for a reference type -- and `null + 1` has to auto-unbox that `null` down to a primitive `int` in order to perform the addition. Unboxing `null` has no number to produce, so it throws instead. This is easy to miss because nothing about the line looks dangerous: `Map.get` genuinely does return `Integer`, and `Integer + int` genuinely does compile.

`getOrDefault(word, 0)` returns `0` -- a real, usable `int`-compatible value -- instead of `null`, for exactly the case that would otherwise throw. `0` is also the correct starting point for "how many times has this word been seen", which is what makes the same one line correct whether it is a word's first occurrence or its hundredth.
