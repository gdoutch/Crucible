One constructor call, twice

return new ArrayList<>(new LinkedHashSet<>(values));

That is the entire function. The inner `new LinkedHashSet<>(values)` does the deduplicating *and* the order-preserving; the outer `new ArrayList<>(...)` just converts the result to the `List` return type asked for.

Which `Set` you reach for is the whole exercise

`new HashSet<>(values)` also removes duplicates -- and gives you back an iteration order with no relationship to insertion order at all, because `HashSet` orders its elements by where they land in its hash table, not by when they arrived. `LinkedHashSet` is the same `Set` contract, plus a linked list threaded through the entries in insertion order, which is what its iterator actually walks. Constructing either one from `values` inserts each element once, in order, and a `Set`'s own rules already reject a second `add` of an equal value -- the only thing that differs between the two classes is what order you get back afterward.
