Sum an Array Without Overflowing

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

One accumulator, one loop

long total = 0;
for (int v : values) {
    total += v;
}
return total;

That is the whole function -- the interesting part is what type total is declared as, not the loop itself.

Java never tells you an int overflowed

If total starts life as an int and only gets widened to long in the return statement, every individual += along the way is still ordinary 32-bit addition. Java's `int` arithmetic never throws or warns on overflow -- it wraps silently to whatever bit pattern falls out, and by the time the final widening runs, the wrong value has already been computed and stored. Declaring `long total = 0;` from the start means every addition, from the first one onward, is already a 64-bit addition.

A `for`-each loop (for (int v : values)) reads each element without needing an explicit index -- and since the loop body only ever reads v, nothing here needs `values` to change.
