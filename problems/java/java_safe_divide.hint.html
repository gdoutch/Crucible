Division Java Will Not Warn You About

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

Check both special cases before dividing at all

if (b == 0) {
    return new DivideResult(DivideStatus.DIVIDE_BY_ZERO, 0);
}
if (a == Integer.MIN_VALUE && b == -1) {
    return new DivideResult(DivideStatus.OVERFLOW, 0);
}
return new DivideResult(DivideStatus.OK, a / b);

There is no exception waiting to be caught here

It is tempting to wrap `a / b` in a `try` and catch `ArithmeticException`, on the theory that "division has problems, exceptions report problems". That works for `b == 0` -- Java does throw `ArithmeticException` for that one -- and does *nothing at all* for `Integer.MIN_VALUE / -1`. Unlike some other languages, Java's `int` arithmetic never checks for overflow, on any operator, ever: `/` for this specific pair of operands simply computes `Integer.MIN_VALUE` again (the bit pattern that falls out of the hardware operation) and returns it as an entirely ordinary, unremarkable-looking `int`. There is no exception, no error, nothing to catch -- a `try`/`catch` built to detect this case catches nothing, ever, because nothing is ever thrown.

The only way to detect it is to check for it explicitly, with an `if`, *before* the division runs -- the same discipline the `b == 0` check already uses, just for a condition Java itself will not flag.
