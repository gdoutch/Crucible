Count Words Without split()'s Empty-String Surprise

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

import java.util.Scanner;

public class Solution {
    public static int countWords(String text) {
        Scanner scanner = new Scanner(text);
        int count = 0;
        while (scanner.hasNext()) {
            scanner.next();
            count++;
        }
        return count;
    }
}

Why `String.split` gets the empty-input case wrong

`String.split(regex)` is documented to split around matches of the regex and return the resulting substrings as an array -- and for a string with no matches at all (an empty string has nothing for `\s+` to match), the "resulting substrings" are defined to be the whole input as a single element. That single element happens to be `""`, but it is still one array entry, not zero. The same reasoning applies to a `text` that is entirely whitespace: nothing about calling `.trim()` first changes what `split` does *after* trimming -- `trim()` just turns `" "` into `""` before the identical one-element-array behaviour kicks in.

Why `Scanner` does not have this problem

`Scanner.hasNext()` and `Scanner.next()` are specified in terms of finding an actual token -- a maximal run of non-whitespace characters -- and reporting whether one exists. An empty or all-whitespace `text` simply has no such run anywhere in it, so `hasNext()` returns `false` immediately and the loop body never executes, leaving `count` at its initial `0`. There is no intermediate array representation with its own "at least one element" rule to work around -- the tokens are produced one at a time, and there are exactly as many of them as there really are words.

Cost

O(n) in the length of `text` -- `Scanner` scans the characters once to find token boundaries, and each token found is one `next()` call.
