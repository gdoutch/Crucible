Count Words Without split()'s Empty-String Surprise

Let Scanner produce only real tokens

Scanner scanner = new Scanner(text);
int count = 0;
while (scanner.hasNext()) {
    scanner.next();
    count++;
}
return count;

new Scanner(text) wraps a string in the same token-reading interface you would use to read real input -- `hasNext()` / `next()` only ever see genuine, non-empty, whitespace-delimited tokens.

The one-liner that looks right and is not

text.split("\\s+").length is the instinctive first attempt, and it is wrong for exactly the input that matters most to get right: an empty (or all-whitespace) `text`. `split` is specified to always return at least one element -- "the whole input, unsplit" still counts as one piece even when that piece is the empty string -- so `"".split("\\s+")` comes back as an array of length `1`, not `0`. Trimming first does not help: `" ".trim()` is `""`, and splitting *that* still returns one element.
