Reverse a String (Which You Cannot Mutate)

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

public class Solution {
    public static String reversed(String text) {
        char[] chars = text.toCharArray();
        int left = 0;
        int right = chars.length - 1;
        while (left < right) {
            char temp = chars[left];
            chars[left] = chars[right];
            chars[right] = temp;
            left++;
            right--;
        }
        return new String(chars);
    }
}

Why `text` itself is never modified -- and could not be

Every `String` instance in Java is immutable by design: once constructed, its internal character data never changes, for the lifetime of that object. There is no `String` method anywhere that rewrites a character in place, and reassigning the parameter -- `text = something;` -- inside the method only changes which object the *local variable* `text` refers to, with zero effect on whatever the caller passed in, because Java hands methods a copy of the reference, not a way to reach back into the caller's own variable. `text.toCharArray()` sidesteps the whole question: it copies every character into a fresh `char[]` that this method fully owns, swaps elements of *that*, and builds the return value from it with `new String(chars)`. `text` is read from, once, and never written to at all.

Why `left < right`, not `left <= right`

For an odd-length string, the two indices meet at the middle character, which would be swapped with itself -- harmless, but pointless. < stops the loop the moment that would happen. For an even-length string, `left` and `right` cross by one without ever being equal, and `<` stops that case correctly too, with no separate branch for either parity.

Why the empty and single-character cases need no guard

An empty string has `chars.length == 0`, so `right == -1` and `left < right` (`0 < -1`) is false immediately. A one-character string has `left == right == 0`, also false immediately. Both fall straight through to `return new String(chars);` with the array unchanged -- exactly the right answer, reached the same way a longer string's reversal is, with no `if` needed to detect either case specially.

Cost

O(n) in the length of `text` -- one array copy via `toCharArray()`, one pass swapping pairs, and one new `String` built from the result.
