Remove While Iterating, Without ConcurrentModificationException

Hint

A nudge in the right direction. The full answer is on the worked-solution page, so nothing below gives it away.

One call does the whole job

values.removeIf(v -> v % n == 0);

`List.removeIf` walks the list once, internally, and removes every element the predicate accepts -- there is no externally visible iterator for anything to invalidate, because the removal happens inside the one call that owns the whole operation.

What throws, and why it is not obvious from reading the loop

`for (Integer v : values) { if (v % n == 0) values.remove(v); }` looks completely ordinary -- nothing about the syntax suggests danger. The `for`-each is sugar for calling `values.iterator()` once and driving it with `hasNext()`/`next()`; that iterator counts structural modifications to the list independently of the list's own size, and `values.remove(v)` is a modification the iterator did not make and does not know about. The very next time the loop asks the iterator for anything -- which, for a list of any real length, is almost immediately -- it notices the mismatch and throws `ConcurrentModificationException`. This happens on the *first* removal, not only when there is more than one.

An explicit `Iterator<Integer>`, calling its *own* `.remove()` method instead of the list's, is the one form of removing mid-iteration Java actually allows -- because that call updates the iterator's own bookkeeping as part of removing.
