Remove Duplicates, Keep First-Seen Order

Worked solution

This page contains the complete answer and explains why each part of it is there.

The code

import java.util.ArrayList;
import java.util.LinkedHashSet;
import java.util.List;

public class Solution {
    public static List<Integer> dedupePreserveOrder(List<Integer> values) {
        return new ArrayList<>(new LinkedHashSet<>(values));
    }
}

Why `LinkedHashSet`, specifically, is the correct choice

`HashSet` and `LinkedHashSet` share the exact same `Set` contract -- no duplicate elements, membership tested via `equals`/`hashCode` -- and differ only in what their iterator promises about order. `HashSet` makes no promise at all: its iteration order follows the internal hash table's bucket layout, which has nothing to do with insertion order and can even change between runs. `LinkedHashSet` additionally maintains a doubly linked list threading through its entries in the order they were inserted, and its iterator walks *that* instead of the hash buckets. For "deduplicate, keep first-seen order", that is not a workaround bolted onto a `Set` -- it is the one property `LinkedHashSet` exists to add on top of `HashSet`'s.

Why the constructor alone is enough

`new LinkedHashSet<>(values)` iterates `values` once, in order, calling `add` for each element. A `Set`'s `add` is specified to do nothing (and report `false`) when the element is already present -- so the first occurrence of each distinct value is recorded, in the position it arrived at, and every later occurrence is silently rejected without disturbing what is already there. There is no additional loop or membership check to write by hand; the constructor already performs exactly that sequence of operations.

Why the final `ArrayList` wrap does not affect ordering

`new ArrayList<>(collection)` copies its argument's elements in whatever order that argument's own iterator produces them -- for a `LinkedHashSet`, that is the insertion order already established by the step above. The conversion to `List` is the last, order-preserving step, not a second place order could go wrong.

Cost

O(n) average in the length of `values` -- each element does one hash-set insert (O(1) average) plus, for a first occurrence, one linked-list append; converting to an `ArrayList` at the end is a single O(k) copy of the k distinct survivors.
