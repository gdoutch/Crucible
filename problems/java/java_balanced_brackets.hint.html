Balanced Brackets With an ArrayDeque

Push opens, check-then-pop closes

Deque<Character> openBrackets = new ArrayDeque<>();
for (char c : text.toCharArray()) {
    if (c is an opening bracket) {
        openBrackets.push(c);
    } else if (c is a closing bracket) {
        // is openBrackets empty, or does .pop() not match c?
        // either one means "unbalanced" -- return false right here
    }
    // anything else: ignore it entirely
}
return openBrackets.isEmpty();

Reach for `Deque`, not `java.util.Stack`

`java.util.Stack` still exists and still works, but it predates the collections framework, extends `Vector`, and carries synchronization on every operation that this single-threaded function gets no benefit from at all -- the standard library's own documentation says to prefer `Deque` instead. `Deque` (backed by `ArrayDeque`) provides `push`, `pop` and `peek` directly, with the same LIFO stack semantics, so nothing about how the code reads has to change to make the switch.

`.pop()` and `.peek()` on an empty `Deque` throw `NoSuchElementException` -- a real, documented exception, but this function needs to return `false` for an unmatched closing bracket, not let one propagate. Check `.isEmpty()` first.
