Check before you record

Map<Integer, Integer> seen = new HashMap<>();
for (int i = 0; i < values.length; i++) {
    int complement = target - values[i];
    if (seen.containsKey(complement)) {
        return new int[] { seen.get(complement), i };
    }
    seen.put(values[i], i);
}

Order matters here more than it looks like it should

If `values[i]` is recorded into `seen` *before* checking for its own complement, and `target` happens to be exactly `2 * values[i]`, the lookup for `complement` finds the entry that was just added -- for *itself*. That returns `{ i, i }`, the same index twice, which is not a pair of two distinct elements at all. Checking the map first and only inserting afterward means the map, at the moment of any given check, only ever contains indices strictly *before* `i` -- so a match is always a genuinely different, earlier element.

That ordering is also why the match found is always the smaller index: by the time index `i` looks itself up, everything in the map arrived before it.
